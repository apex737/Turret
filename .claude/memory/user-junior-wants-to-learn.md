사용자는 취업 준비 중인 주니어 임베디드 개발자다. 과거에 STM32F411RE로 TDoA 음원 각도 추정을 직접 해 본 경험이 있다.

변천: 2026-10-11 Remark.md(손 재구현) → 2026-10-14 "AI가 빠르게 구현, 복습은 나중" → 2026-10-22 `learning/GUIDE.md` v2.1 도입 (구현 속도는 그대로, 트리거 점검으로 숙지를 잰다).

**파츠 등급(problem.md)의 뜻 — 2026-10-22 사용자 정정:** "구현" 등급은 실무에서 너무 중요해서 *직접 구현할 수 있을 만큼 숙지*해야 한다는 뜻이다. 사용자가 지금 손으로 짜겠다는 뜻이 아니다. 나는 이걸 "사용자가 직접 작성"으로 잘못 읽고 Step9A 결합 규칙을 빈칸(stub)으로 남겼다가 지적받았다.

**설명 수준 (2026-10-25 하향, 사용자 요청):** 신호처리 기초 용어(스펙트럼, dB, 주파수 응답, 나이퀴스트, 필터, 고조파, 파장)를 아직 자유롭게 쓰지 못한다. 내 답변 중 이해 못 한 것이 많다고 함. 용어는 나올 때마다 숫자 예시로 풀고, 한 문단에 새 용어 하나, 인과 사슬은 한 단계씩. concepts에 기록하기 전에 바로 아래 기초를 1 ~ 3문항으로 먼저 확인한다 (GUIDE v2.3 7절 3).

**How to apply:**
- 구현은 등급과 관계없이 AI가 끝까지 빠르게 한다. 사용자 구현을 기다리거나 빈칸을 남기지 않는다. GUIDE "빠른 구현은 포기하지 않는다. 점검은 짧게, 모른다고 개발이 멈추지 않는다."
- 등급은 점검의 깊이에 쓴다: 구현 등급 파츠(수집·버퍼·통신·유실 처리, 9A 결합, 10 통합)는 T4에서 복원·고장 진단 문항을 우선.
- 세션 시작: README.md, problem.md, learning/GUIDE.md, learning/profile.md, learning/concepts.json(오늘 Step 키워드 한 줄, 대기 항목 최대 2개).
- 트리거: T1 분석 돌리기 직전 1(예측), T2 Action 적용·커밋 전 1 ~ 3, T3 상수 변경 1 ~ 2, T4 게이트 5 ~ 8. 한 덩어리 1 ~ 2시간에 T1 ~ T3 합쳐 최대 3번. T2·T3 미답이면 그 Action만 커밋 보류, 나머지 작업은 계속.
- 교재·도우미 페이지·개념 설명문은 만들지 않는다. 결론 끝에 "기대는 개념:" 줄.
- **GUIDE v2.4 (2026-10-25):** 세션 시작·관련 작업 때 R 복습(1 ~ 2문항, 속도 예산 밖)으로 concepts의 "이해함 아님" 개념을 다시 묻는다. 맞히면 AI가 understood=true, 틀리면 정답을 짧게 알려 주고 wrong_count +1 (AI만 올림, 절대 줄이지 않음). 하루 끝 TIL(learning/TIL/)은 사실 확인만.

관련: [[workflow-baseline-pivoting]], [[feedback-concise-decision-docs]]
- **GUIDE v2.5 (2026-10-27, 사용자 요청):** 결론·결정·상수의 근거가 되는 실험은 모두 `py`(계산, Tools/<영역>/)와 `ipynb`(흐름, Tools/notebooks/)를 따로 만든다. 노트북은 처리 순서대로 단계마다 그림, 한 창 손 추적, 결론 후보(사용자 확인 전)로 끝나며 AI가 실행해 출력을 저장해 넘긴다. AI는 대화에서 결론을 단정하지 않고 "후보 + 노트북 경로 + 볼 절"로 보고. 사용자가 노트북을 보기 전에는 결정·문서·상수 변경 금지. 계기: "실험 결과가 전부 블랙박스라 아쉽다".
