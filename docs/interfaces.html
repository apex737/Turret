1. 형식 — v2 원파형·결과 패킷

칸 하나가 1바이트, 한 줄이 4바이트(32비트 워드)다. 칸에 마우스를 올리거나 눌러 설명을 본다. 모든 값은 little endian이다.

v2 헤더 (20 B) — 원파형 RAW 0x01과 결과 0x02가 같이 쓴다

sync 4
헤더 16
payload ch×n×2 (2프레임 12,288 B)
CRC 2

2프레임 RAW 패킷 = 20 + 12,288 + 2 = 12,310 B, 전송 약 134 ms

v2 결과 payload (40 B, type 0x02) — 패킷 62 B

RAW payload는 채널이 바깥 루프다: ch0 직전 | ch0 현재 | ch1 직전 | ch1 현재 | ch2 직전 | ch2 현재, 샘플마다 uint16. 결과 패킷은 같은 frame_seq의 RAW와 짝이다.

1. 형식 — v3 PCM·DOA 패킷

v3 헤더 (24 B) — PCM 0x03과 DOA 0x04가 같이 쓴다

sync 4
헤더 20
PCM payload 3 × 256 × 2 = 1,536 B
CRC 2

PCM 패킷 = 24 + 1,536 + 2 = 1,562 B, 20.48 ms마다 하나 · DOA 패킷 = 24 + 52 + 2 = 78 B

DOA payload (52 B, type 0x04)

PCM payload: ch0[256] | ch1[256] | ch2[256], 샘플마다 int16. DOA 패킷 헤더의 drop·ovr·cpu 칸은 0이고 qdrop만 참고용으로 실린다.

little endian 예: seq = 258 = 0x00000102는 offset 8부터 02 01 00 00 순서로 놓인다. 작은 자리가 앞(낮은 주소)이다.

×16은 12비트 범위를 16비트로 옮겨 FIR 출력의 소수 아래 4비트를 남긴다. 반올림 규칙이 PC와 같아야 같은 디지털 입력에서 비트 단위로 비교할 수 있다 (MCU·PC 차이 기준 ≤ 2 LSB, 실측 최대 1 LSB).

출력 위상: y[k] = Σ b[j]·x[4k − j] — 블록의 첫 샘플 시점에 맞춘다 (호스트 시험으로 확인, 처음 가정한 4k + 3은 틀렸음).

2. 의미 — 시간축: 모두가 같이 쓰는 시계는 샘플 번호

ADC 프레임 번호(frame_seq, 1부터)가 곧 시간이다. PC가 받은 시각에는 UART·OS 지연이 섞이므로 쓰지 않는다.

값식예
PCM 블록의 첫 샘플 번호(frame_seq − 1) × 256frame_seq 50 → 12,544
그 시각 (초)샘플 번호 ÷ 12,50012,544 → 1.0035 s
DOA 관측 창s0 ~ s0 + 6,250 (0.5 s), 다음 창은 + 3,072s0 = 25,000 → 2.0 ~ 2.5 s

3. 규칙 — 수신 파서 절차

UART는 패킷 경계가 없는 바이트 흐름이다. 수신단은 아래 순서로 패킷을 잘라 낸다. PCM payload 안에는 FF FF FF FF가 나올 수 있으므로 sync만 믿지 않고 버전·종류·길이·CRC가 모두 맞아야 받는다.

① sync 찾기 — 버퍼에서 FF FF FF FF
없으면: 마지막 3바이트만 남기고 버림 (sync가 경계에 걸쳐 있을 수 있음)
↓
② 헤더 검증 — ver 2 이면 20 B, ver 3 이면 24 B 헤더로 읽고 종류별로 확인
RAW: ch ≠ 0, len = ch × n × 2 ≤ 64 KB · 결과: len = 40 · PCM: 1 ≤ ch ≤ 8, len = ch × n × 2 · DOA: len = 52
틀리면: 1바이트만 버리고 ①로 (bad_hdr 증가)
↓
③ 길이만큼 모일 때까지 대기 — 헤더 + len + 2
모자라면: 다음 수신까지 기다림
↓
④ CRC-16/CCITT-FALSE — ver부터 payload 끝까지 (binascii.crc_hqx(data, 0xFFFF))
틀리면: 1바이트만 버리고 ①로 (crc_fail 증가 — payload 속 가짜 sync도 여기서 걸러짐)
↓
⑤ 받음 — 패킷만큼 버퍼에서 떼어 내고, (버전, 종류)별로 seq가 1씩 늘었는지 확인 (아니면 seq_gap 증가). v2, PCM, DOA는 번호를 따로 센다.
