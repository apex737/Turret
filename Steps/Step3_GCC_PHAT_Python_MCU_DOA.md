## 4. GCC-PHAT 파이프라인

Python(`gcc_phat.py`의 `analyze()`)과 MCU(`tdoa.c`의 `tdoa_process()`)가 같은 순서, 같은 상수로 계산한다.

```
[직전 | 트리거] 2048샘플 x 3채널
  1) onset 탐색 (정수 연산)        → 소리 시작 위치
  2) 구간 자르기                   onset 50샘플 전부터 250샘플(5ms), 3채널에 같은 구간
  3) 평균 제거 + 창(Tukey)
  4) FFT 512점 (뒤는 0으로 채움)   → 채널별 스펙트럼 X1, X2, X3
  5) 교차 스펙트럼                 R = X_j · conj(X_i)      (쌍 3개)
  6) 대역 제한 + PHAT              500~3000Hz(빈 6~30)만 남기고 R / (|R| + ε)
  7) IFFT                          → 상관 곡선. 지연 -13 ~ +13샘플만 사용
  8) 피크 + 2차 보간               → tau_ij (소수점 샘플)
  9) 최소제곱                      tau 3개 → 방향 벡터 (ux, uy)
 10) atan2 → 각도,  벡터 길이 → norm
```

### 4.1 부호와 각도 규칙

- `tau_ij` = (j 도달 시각) − (i 도달 시각) [샘플]. **양수 = MIC j가 MIC i보다 늦게 들음.**
- 쌍은 (1,2), (1,3), (2,3). 세 값은 `tau12 + tau23 = tau13`을 만족해야 함.
- 마이크 배치: **한 변 7cm 정삼각형**(가정). 중심에서 MIC1 방향이 0°, 위에서 봤을 때 반시계가 +. MIC2 = +120°, MIC3 = −120°.
- 번호가 시계 방향이면 Python은 `--cw`, MCU는 `TDOA_MIC_CW 1`.

### 4.2 단계별로 왜 하는가

| 단계 | 이유 |
|---|---|
| onset 구간만 사용 | 방향 정보는 첫 직접음에 있음. 뒤쪽은 벽·책상 반사음이 섞임 |
| 3채널 공통 구간 | 지연은 "같은 시간 창 안에서의 상대적 밀림"이라 구간이 다르면 의미가 없음 |
| 평균 제거 | 바이어스(≈2048)는 소리가 아님. 남기면 0Hz에 큰 성분이 생김 |
| 창 | 구간 양 끝이 갑자기 잘리면 가짜 주파수 성분이 생김. 양 끝 20%만 코사인으로 줄임 |
| 교차 스펙트럼 | 두 채널의 **위상 차이**가 주파수마다 들어 있음. 지연 τ는 위상 기울기로 나타남 |
| 대역 제한 | 신호가 있는 대역만 사용. 시간 영역 필터 대신 **대역 밖 빈을 0으로** 만듦 |
| PHAT | 크기로 나눠 위상만 남김 → 모든 주파수가 같은 무게로 투표 → 피크가 뾰족해지고 채널 간 게인 차이에 둔감 |
| ε (0.01 × 최대 크기) | 신호가 거의 없는 빈은 위상이 잡음. 그대로 1로 키우면 잡음이 투표에 참여함 |
| 탐색 범위 ±13샘플 | 7cm를 소리가 지나는 시간 = 10.2샘플. 그보다 큰 지연은 물리적으로 불가능 (+여유 2) |

### 4.3 2차 보간 — 샘플 사이 위치 구하기

- 1샘플 = 20µs = 6.86mm. 마이크 간격 7cm에서는 지연이 최대 10.2샘플뿐이라, **정수 샘플만 쓰면 각도가 약 5.6° 단위**로 끊김.
- 상관 곡선의 피크와 양옆 두 점(y0, y1, y2)을 포물선으로 보고 꼭짓점 위치를 구함:

```
p    = 0.5 · (y0 − y2) / (y0 − 2·y1 + y2)      (−0.5 ~ +0.5 샘플)
tau  = 피크 위치 + p
peak = y1 − 0.25 · (y0 − y2) · p
```

- "샘플링 주파수를 높이는 효과"처럼 보이는 이유: 상관 곡선은 대역이 제한된 매끄러운 곡선이라, 샘플 사이의 값이 주변 점들로 결정됨.
- 상관 곡선을 16배 촘촘하게 계산한 것(`up=16`)과 원래 간격에서 2차 보간만 한 것(`up=1`)의 차이는 **최대 0.015샘플** → MCU는 2차 보간만 사용.
- 계산상 지연 오차 0.1샘플 ≈ 각도 0.5° (norm = 1일 때).

### 4.4 지연 3개 → 각도 (최소제곱)

- 평면파 가정: 음원 쪽 단위 벡터를 u라 하면 `(p_j − p_i) · u = −c · tau_ij / fs`
- 식 3개, 미지수 2개(ux, uy) → 최소제곱. 배치가 고정이므로 MCU는 풀이 행렬(2×3)을 `tdoa_init()`에서 한 번만 계산.
- 각도 = `atan2(uy, ux)`

### 4.5 품질 지표 3가지

| 지표 | 뜻 | 쓰임 |
|---|---|---|
| **peak** | 상관 피크 높이(0~1). 대역 전체가 같은 지연으로 정렬되면 1 | 세 쌍 중 최솟값이 **0.5 미만이면 신뢰 낮음**으로 판정 |
| **closure** | `tau12 + tau23 − tau13`. 세 쌍이 서로 모순 없으면 0 | 정답 없이 볼 수 있는 일관성 지표 |
| **norm** | 방향 벡터 길이. 음원이 멀고 마이크와 같은 평면이면 1 | 1보다 작으면 음원이 위/아래에 있음. 1보다 크면 배치 가정이 틀린 것 |

- peak 0.5 기준의 근거(이전 캡처 124개): peak ≥ 0.5인 49개는 closure 0.5샘플 이내가 92%, 전체로는 50%.
- norm이 작으면 각도가 불안정해짐 (오차가 1/norm에 비례).

**신뢰 판정 규칙** (PC와 MCU가 같음. 세 조건을 모두 만족해야 신뢰 가능):

| 조건 | 값 | 이유 |
|---|---|---|
| 세 쌍 중 가장 낮은 peak | 0.5 이상 | 위 근거 |
| norm 하한 | 0.3 이상 | 음원이 거의 위/아래에 있으면 수평 각도가 불안정 |
| norm 상한 | 1.2 이하 | 1을 크게 넘는 값은 물리적으로 불가능 (엉뚱한 피크를 고른 것) |

- 세션 로그 8개(캡처 235개)에 적용하면 220개(94%)가 통과. norm 0.3 미만은 8개(3%).
- norm 하한 0.3은 데이터에서 경계가 보여서 정한 값이 아님. 낮은 norm 표본이 적어 오차가 1/norm에 비례한다는 계산에 근거함.

### 4.6 onset 탐색 — 정수 연산으로 통일

```
편차[i] = 3채널 중 최대 |n·x[i] − 합|          (= |x − 평균| × n, 나눗셈 없음)
잡음    = 앞쪽 1/4 구간의 편차 평균
문턱    = max(8 × 잡음, 최대 편차 / 20)
onset   = 편차가 문턱을 처음 넘는 위치           (없으면 최대 편차 위치)
```

- 처음엔 중앙값 기반이었으나, MCU와 **정확히 같은 결과**를 내기 위해 정수 연산으로 변경.
- 캡처 116개에서 변경 전후 비교: onset 차이 중앙값 0샘플, 각도 차이 95%가 0.15° 이내 (1개는 16.9°).

## 5. 파라미터

| 파라미터 | 값 | Python | MCU (`tdoa.h`) |
|---|---|---|---|
| 대역 | 500~3000Hz | `--band` | `TDOA_BAND_LO_HZ`, `TDOA_BAND_HI_HZ` |
| 분석 구간 | 5ms (250샘플) | `--win` | `TDOA_WIN` |
| onset 전 여유 | 1ms (50샘플) | `--pre` | `TDOA_PRE` |
| FFT 크기 | 512 | 자동 (구간의 2배 이상인 2의 거듭제곱) | `TDOA_NFFT` |
| 최대 지연 | ±13샘플 | `--max-lag` (간격에서 자동 계산) | `TDOA_MAX_LAG` |
| PHAT ε | 0.01 | `--eps` | `TDOA_PHAT_EPS` |
| 마이크 간격 | 0.07m | `--spacing` | `TDOA_SPACING_M` |
| 신뢰 기준: peak | 0.5 이상 | `--min-peak` | `TDOA_MIN_PEAK` |
| 신뢰 기준: norm | 0.3 ~ 1.2 | `--min-norm`, `--max-norm` | `TDOA_MIN_NORM`, `TDOA_MAX_NORM` |

**두 쪽 값이 다르면 비교가 맞지 않는다.** 한쪽을 바꾸면 다른 쪽도 같이 바꿀 것.

### 5.1 대역을 500~3000Hz로 정한 근거

이전 캡처 124개(설정이 일관되지 않은 데이터)에서 대역 5종 × 구간 4종 비교. "kept"는 peak ≥ 0.5인 캡처 수.

| 대역 | 구간 5ms: kept | closure 0.5샘플 이내 |
|---|---|---|
| 150~2000Hz | 49 | 86% |
| **500~3000Hz** | 49 | **92%** |
| 1000~4000Hz | 48 | 85% |
| 2000~5000Hz | 37 | 86% (구간 2 ~ 3ms에서는 71~72%) |
| 1000~8000Hz | 13 | 100% (수율이 낮음) |

- 스펙트럼에서 에너지가 큰 2 ~ 6kHz가 유리할 것이라는 예상과 달리 **높은 대역이 가장 나빴음**. 2000 ~ 5000Hz에서는 상관 곡선의 두 번째 봉우리가 피크의 약 0.8배까지 올라와(500~3000Hz는 확인한 캡처에서 0.1 미만) 엉뚱한 봉우리를 고르기 쉬움.
- 구간 길이(2~10ms)는 큰 차이 없음.
- 데이터 품질이 고르지 않았으므로, 대상 소리가 정해지면 `gcc_phat.py dumps\<세션> --sweep`으로 다시 확인.

### 6.1 doa_live.py

- 패킷이 올 때마다 각도를 계산해 나침반에 표시. **COM 포트는 한 프로그램만 열 수 있으므로 dump_viewer.py는 닫고 실행.**
- 실행할 때마다 `dumps\<날짜_시각>\` 폴더를 새로 만들어 저장 → MCU를 리셋해도 덮어쓰지 않음.

| 저장 파일 | 내용 |
|---|---|
| `f_<seq>.npz` | 원파형 (나중에 다른 설정으로 다시 분석 가능) |
| `log.csv` | 캡처별 지연, closure, peak, 각도, norm, MCU 결과, MCU와의 차이, 계산 시간. `src` = pc / mcu, `mcu_valid` = MCU 판정, `d_valid` = PC 판정과 다르면 1 |

| 화면 요소 | 뜻 |
|---|---|
| 큰 숫자 | 가장 최근 각도 |
| 검은 화살표 | 가장 최근 캡처. 길이 = norm |
| 파란 점 | 최근 30개의 신뢰 가능한 캡처 (오래될수록 흐림) |
| 회색 점선 화살표 | 신뢰 낮음 (4.5의 판정 규칙). 통계에서 제외 |
| 둘째 줄 `MCU …` | MCU가 계산한 각도, PC와의 차이, 계산 시간 |

- 펌웨어 모드에 따라 동작이 달라짐 (7.6):
  - 원파형 + 결과: PC가 계산한 값을 표시하고 MCU 값과의 차이를 덧붙임. npz 저장.
  - 결과만: **MCU가 계산한 값과 MCU의 판정을 그대로 표시.** npz는 저장되지 않고 `log.csv`만 남음.
- 종료(Ctrl+C) 시 요약 출력. 결과 전용 모드에서는 계산 시간과 결과 사이 간격도 나옴. **"각도 평균 / 흩어짐"은 음원이 한 자리에 있었을 때만 의미가 있다.** 돌아가며 스냅한 세션에서는 무시.

## 7. MCU 구현

### 7.1 CMSIS-DSP 가져오기

### 7.2 IDE 설정

Properties → C/C++ Build → Settings → Tool Settings (Configuration: Debug)

| 위치 | 항목 | 값 |
|---|---|---|
| MCU/MPU Settings | Floating-point unit | FPv4-SP-D16 (기본값) |
| MCU/MPU Settings | Floating-point ABI | Hardware implementation (기본값) |
| MCU/MPU GCC Compiler → Include paths | 추가 | `../Drivers/CMSIS/DSP/Include`, `../Drivers/CMSIS/DSP/PrivateInclude` |
| MCU/MPU GCC Compiler → Optimization | Optimization level | Optimize for speed (`-Ofast`) |

- `ARM_MATH_CM4` 같은 define은 이 버전에서는 필요 없음.
- 소스는 `Drivers`가 이미 빌드 대상 폴더라 따로 등록하지 않아도 컴파일됨.
- FPU를 켜는 코드는 CubeMX가 만든 `SystemInit()`에 있음. 하드웨어 실수 옵션으로 빌드한 코드는 FPU가 꺼져 있으면 첫 실수 연산에서 HardFault가 나므로, 정상 동작하면 켜져 있는 것.
- `-Ofast`의 대가: 디버깅 시 한 줄씩 실행이 뛰고 지역변수가 안 보일 수 있음. 되돌릴 때는 None (`-O0`).

### 7.3 tdoa.c 구조

| 함수 | 하는 일 |
|---|---|
| `tdoa_init()` | FFT 준비, 창 계산, 마이크 좌표 → 최소제곱 풀이 행렬(2×3) 계산. 부팅 시 한 번 |
| `tdoa_process(frames, nframes, out)` | 4절의 1)~10). 프레임 1개 또는 2개(직전 + 트리거)를 이어붙인 것으로 취급 |
| `find_onset()`, `deviation()`, `sample()` | onset 탐색. 두 프레임을 복사해 붙이지 않고 번호로 읽음 |

- 고정 버퍼: 채널별 스펙트럼 3 × 512, 작업용 512, 상관 곡선 512, 창 250 (float) ≈ 11KB
- `arm_rfft_fast_f32`는 **입력 버퍼를 덮어씀** → 입력은 매번 새로 채움.
- 역변환 결과에서 지연 l의 값은 `corr[l]`, 음수 지연은 뒤쪽 `corr[512 + l]`에 있음.
- 피크가 1이 되도록 `512 / (2 × 25)`를 곱함 (25 = 대역 안의 빈 수).

### 7.4 캡처와 연결

```
capture_on_frame()
 ├ 트리거 → dump_send_frames()      원파형(RAW) 송신 시작 (134ms)
 └ 송신 성공 → on_trigger 콜백 ──▶ app.c: on_capture()
                                     ├ DWT 사이클 카운터로 시간 측정
                                     ├ tdoa_process()
                                     └ dump_queue_result()   결과 패킷 대기
main 루프: dump_poll() ──▶ RAW 송신이 끝나면 결과 패킷 송신
```

- 결과 전용 모드에서는 원파형 송신 단계가 빠지고 트리거에서 바로 콜백으로 감 (7.6).
- `capture_set_trigger_cb()`: capture가 tdoa를 직접 알지 못하게 콜백으로 연결.
- 콜백 시점에 `stat.prev`는 아직 직전 프레임 (5단계에서 덮어쓰기 전).
- 결과 패킷은 버퍼가 따로 있어 RAW 송신 중에도 만들어 둘 수 있음. 대기 칸은 1개.

### 7.5 결과 패킷 (type 0x02)

RAW와 같은 20바이트 헤더(ch = 0, n = 0, len = 40) + payload 40바이트 + CRC 2바이트 = 62바이트. `frame_seq`가 같은 RAW 패킷과 짝.

| offset | 크기 | 필드 | 내용 |
|---|---|---|---|
| 0 | 12 | tau[3] | tau12, tau13, tau23 [샘플] (float) |
| 12 | 12 | peak[3] | 쌍별 피크 높이 (float) |
| 24 | 4 | angle_deg | 방향 [deg] (float) |
| 28 | 4 | norm | 방향 벡터 길이 (float) |
| 32 | 2 | onset | 소리 시작 위치 [샘플] |
| 34 | 2 | win_start | 분석 구간 시작 위치 [샘플] |
| 36 | 4 | proc_us | 계산 시간 [µs] |

- C 쪽 `dump_result_t`(dump.h)와 Python 쪽 `RESULT_FMT = "<3f3fffHHI"`(dump_viewer.py)가 같아야 함.
- `seq`는 패킷 종류와 관계없이 보내는 순서대로 증가 → RAW만 세면 번호가 하나씩 건너뜀.
- 헤더 flags의 `0x08`(`DUMP_FLAG_VALID`) = MCU가 이 결과를 신뢰 가능으로 판정 (7.7). 결과 패킷에만 쓰임.

### 7.6 동작 모드 — `CAPTURE_SEND_RAW`

`capture.h`의 한 줄(또는 IDE Define symbols의 `CAPTURE_SEND_RAW=0`)로 선택.

| | `1` (검증용) | `0` (운용용, 결과 전용) |
|---|---|---|
| 보내는 것 | 원파형 12.3KB + 결과 62B | 결과 62B만 |
| 송신 시간 | ≈134ms | 1ms 미만 |
| holdoff 기본값 (`CAPTURE_HOLDOFF_DEFAULT`) | 50프레임 (≈1초) | 10프레임 (≈0.2초) |
| PC 화면 | PC 계산값 + MCU와의 차이 | MCU 계산값 그대로 |
| 저장 | npz + log.csv | log.csv만 |

- 결과 전용 모드에서는 원파형 송신을 건너뛰고 콜백만 부름. 트리거 판정, 직전 프레임 보관, 잡음 학습은 두 모드가 같음.
- **결과 전용 모드에서는 원파형이 남지 않음** → 나중에 다시 분석하거나 PC와 비교할 수 없음. 알고리즘이나 파라미터를 바꾼 뒤에는 모드 1로 한 번 검증할 것.
- `dump_viewer.py`는 결과 패킷을 건너뛰므로 결과 전용 모드에서는 아무것도 표시하지 않음.

### 7.7 MCU 신뢰 판정 — `tdoa_result_t.valid`

- `tdoa_process()` 마지막 단계에서 4.5의 규칙으로 판정해 `valid`에 기록.
- `app.c`의 `on_capture()`가 `valid`이면 결과 패킷 flags에 `DUMP_FLAG_VALID`를 켬.
- **터렛 제어는 `r.valid`가 참일 때만 `r.angle_deg`를 써야 함.**
- 기준값을 바꿀 때는 `tdoa.h`의 상수 3개와 PC 옵션(`--min-peak`, `--min-norm`, `--max-norm`)을 같이 바꿀 것.

## 9. 측정에서 관찰한 것과 한계

- **정밀도**: 같은 자리 반복 표준편차 1.3°.
- **일관성**: 돌아가며 스냅하면 각도가 순서대로 따라 움직임 (예: −93° → −63° → −19° → +7° → +52°). closure 중앙값 0.02~0.03샘플.
- **norm이 방향에 따라 다름**: −40°~0° 쪽은 0.9 이상, +50°~+100° 쪽은 0.45~0.55. 그쪽에서 위에서 스냅했거나, 배치가 정확한 정삼각형이 아닐 수 있음. 같은 높이에서 1m 떨어져 재 보면 구분됨.
- **정확도**: 각 마이크 쪽 스냅 확인과 같은 높이 측정은 마침 (10절). 다만 각도를 아는 위치에서 오차를 수치로 기록한 측정은 없음.

구조적인 한계:

| 한계 | 내용 |
|---|---|
| 갑자기 시작하는 소리 전용 | onset을 찾아 그 주변만 분석. 계속 나는 소리에는 시작점이 없음 (트리거도 안 걸림, Step2 5.7) |
| 수평 방향만 | 마이크 3개가 한 평면. 위/아래는 norm이 작아지는 것으로만 드러남 |
| 평면파 가정 | 음원이 가까우면(수십 cm) 오차가 생김 |
| 음속 고정 | 343m/s. 온도 보정 없음 |
| 갱신 주기 | 원파형을 보내는 모드는 초당 1회 이하. 결과 전용 모드는 holdoff 0.2초 → 초당 최대 약 4~5회. 그 안에서 난 소리는 놓치거나 꼬리에서 잡힘 (8.1) |
| 채널 보정 없음 | 마이크 모듈 간 위상 응답 차이를 보정하지 않음 |
