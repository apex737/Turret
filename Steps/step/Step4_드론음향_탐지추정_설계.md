## 2. 정밀도 식은 어디서 나오나

이 절의 결론은 식 두 개다. 나머지는 이 둘이 왜 그런 모양인지에 대한 설명이다.

```
σ_τ = σφ / (2π·√Σfₖ²) = σφ / (2π·β·√K)        위상 잡음 → 시간 오차
σθ  ≈ (c/d)·√(2/3)·σ_τ                          시간 오차 → 각도 오차
```

### 2.1 지연은 위상의 회전이다: φ = −2π·f·τ

τ는 MIC2가 MIC1보다 소리를 늦게 듣는 시간이다. 사인파 하나만 놓고 보면 "τ초 늦었다"는 "한 바퀴 중 얼마만큼 뒤처졌다"로 바꿔 말할 수 있고, 그 뒤처진 각도가 φ다.

1. 주파수 f인 사인파는 1초에 f바퀴 돈다. 한 바퀴(주기)는 1/f초다.
2. τ초가 몇 바퀴인지는 τ를 주기로 나누면 된다. τ ÷ (1/f) = f·τ 바퀴.
3. 한 바퀴는 2π 라디안이므로 뒤처진 각도는 2π·f·τ다. 늦은 쪽이라 부호가 −다.
4. 식으로 확인하면, MIC1이 cos(2πf·t)를 들을 때 MIC2는 t 자리에 (t − τ)가 들어간다.

```
cos(2πf·(t − τ)) = cos(2πf·t − 2πf·τ)     →     φ = −2π·f·τ
```

같은 100 µs라도 1000 Hz(주기 1 ms)에서는 0.1바퀴(36°), 2000 Hz(주기 0.5 ms)에서는 0.2바퀴(72°)다. τ는 시간 하나인데 위상은 각도라서, 주파수마다 환산이 달라지는 것이다.

실제 소리는 여러 주파수가 섞여 있고 FFT가 그것을 주파수 칸(bin)별로 나눠 준다. k번째 칸의 주파수가 fₖ, 그 칸에서 잰 위상 차이가 φₖ다. τ는 소리가 온 방향이 정하므로 **모든 칸에서 같다.** 그래서 (fₖ, φₖ) 점들을 찍으면 원점을 지나는 직선 위에 놓이고, 그 **기울기 s = −2πτ에 재려는 값이 들어 있다.**

### 2.2 무엇이 측정값이고 무엇이 미지수인가

"τ로 φ를 만들고 그 φ에서 다시 τ를 구하면 순환 아닌가"라는 의문이 생기기 쉽다. 그렇지 않다. 진행 방향은 한쪽이다.

| | 어디서 나오나 | 성격 |
| --- | --- | --- |
| φₖ | 두 마이크 FFT 결과의 각도. `angle(X₂[k]·conj(X₁[k]))` | **측정값.** τ를 몰라도 구해진다 |
| fₖ | k·Fs/N | 이미 아는 값 |
| s | φₖ와 fₖ로 직선을 맞춰 얻음 | 계산 결과 |
| τ | τ = −s / 2π | **구하려는 값** |

φ = −2πfτ는 "τ가 있으면 위상이 이렇게 나온다"는 **모형**이다. 이 모형 덕분에 점들이 직선 위에 있어야 한다는 것을 알고, 그 기울기를 읽어 거꾸로 τ를 얻는다. 예를 들어 500, 1000, 2000 Hz에서 위상을 −17°, −38°, −70°로 쟀다면 아래 2.3절의 식으로 τ ≈ 98.7 µs가 나온다. τ를 모르고 시작했다.

**코드가 하는 GCC-PHAT과 같은 일이다.** 크기를 1로 만들고(PHAT) IFFT한 뒤 최댓값을 찾는 것은, 모든 화살표가 한 방향으로 모이는 t를 찾는 것이다.

```
R(t) = Σₖ cos(φₖ + 2π·fₖ·t)                       IFFT 결과. t = τ에서 모든 항이 1 → 최대 K
R(t) ≈ K − ½·Σₖ (φₖ + 2π·fₖ·t)²                   봉우리 근처 (cos x ≈ 1 − x²/2)
```

둘째 줄의 합이 직선 맞추기의 오차 제곱합과 같은 식이다. 즉 **R을 최대로 하는 것과 오차 제곱합을 최소로 하는 것은 같은 문제**이고, 위 세 점 예에서도 두 방식이 98.68 µs로 일치한다. 코드가 봉우리 찾기를 쓰는 이유는 ±180° 위상 감김을 펼 필요가 없고 탐색 범위(±d/c)로 엉뚱한 해가 걸러지기 때문이다. 이 문서가 직선 맞추기를 쓰는 이유는 정밀도 식이 닫힌 꼴로 나오기 때문이다.

대역이 제한되어 있으므로 R(t)는 델타 함수(침)가 아니라 폭이 있는 봉우리다. 봉우리 꼭대기의 곡률이 −Σ(2πfₖ)²이고, 뾰족할수록 같은 잡음에도 꼭대기 위치가 덜 흔들린다. 아래의 β·√K가 바로 이 뾰족함이다.

### 2.3 기울기를 얼마나 정확히 읽나: σ_τ의 유도

잰 위상에는 잡음이 섞여서 점들이 직선에 정확히 놓이지 않는다. 점 하나의 위상이 흔들리는 정도가 σφ(라디안), 그 결과로 읽어 낸 τ가 흔들리는 정도가 σ_τ다. 점 하나에서 시작해 K개로 넓힌다.

**(1) 점 하나로 읽는다면.** 2.1절의 식을 뒤집으면 τ = −φ/(2πf)다. 위상이 σφ만큼 흔들리면 τ는

```
σ_τ(점 하나) = σφ / (2π·f)          σφ = 0.3 rad → 1000 Hz 점 48 µs, 2000 Hz 점 24 µs
```

같은 위상 오차가 주파수가 2배인 점에서는 절반의 시간 오차가 된다. **분모의 f가 지렛대다.** 원점에서 멀리 있는 점일수록 위아래로 같은 폭을 흔들려도 기울기를 조금밖에 못 바꾼다.

**(2) 같은 주파수의 점이 K개라면.** 서로 독립인 측정 K개를 평균하면 흔들림이 1/√K가 된다.

```
σ_τ = σφ / (2π·f·√K)
```

**(3) 주파수가 서로 다른 점 K개라면.** 원점을 지나는 직선 φ = s·f를 긋고, 점들이 직선에서 벗어난 거리의 제곱합 E가 가장 작아지는 s를 고른다(최소제곱). E를 s로 미분해 0으로 둔다.

```
E(s) = Σ(φₖ − s·fₖ)²     →     dE/ds = −2·Σfₖ(φₖ − s·fₖ) = 0     →     ŝ = Σfₖφₖ / Σfₖ²
```

**(4) 잡음을 넣어 본다.** 잰 위상은 진짜 직선에 잡음이 더해진 것이다. φₖ = s·fₖ + nₖ를 넣으면 진짜 기울기와 오차 항으로 갈라진다.

```
ŝ = s + Σfₖnₖ / Σfₖ²                 두 번째 항이 기울기의 오차
```

**(5) 오차의 크기.** 잡음 nₖ는 칸마다 독립이고 표준편차가 σφ다. 독립인 것들을 더하면 분산끼리 더해지고, 상수 fₖ를 곱한 것은 분산이 fₖ²배가 된다.

```
분자의 분산 = σφ²·Σfₖ²     →     ŝ의 분산 = σφ²·Σfₖ² / (Σfₖ²)² = σφ² / Σfₖ²     →     σ_s = σφ / √Σfₖ²
```

**(6) 기울기를 τ로 바꾼다.** s = −2πτ이므로 2π로 나눈다.

```
σ_τ = σφ / (2π·√Σfₖ²)
```

ŝ의 식은 ŝ = Σfₖ²·(φₖ/fₖ) / Σfₖ²로도 읽을 수 있다. φₖ/fₖ는 점 하나가 말하는 기울기이고, 그것들을 **fₖ²의 무게로 평균**한 것이 답이다. 높은 주파수의 점이 더 정확하니(1번) 더 큰 무게를 받는다.

### 2.4 β와 K는 Σfₖ²에 붙인 이름이다

정밀도를 정하는 것은 **Σfₖ²(쓰는 칸들의 주파수 제곱의 합) 하나**다. 이것을 "개수 × 평균"으로 쪼갠 것이 K와 β다.

```
β² = Σfₖ² / K          주파수 제곱의 평균
Σfₖ² = K·β²     →     √Σfₖ² = β·√K     →     σ_τ = σφ / (2π·β·√K)
```

- **K**는 직선을 맞추는 점의 개수다. 신호가 있는 칸만 센다.
- **β**는 주파수를 제곱해서 평균 낸 뒤 루트를 씌운 값(제곱평균제곱근)이다. 2.3절 (2)번 식과 나란히 놓으면 f 자리에 β가 들어갔을 뿐이다. 즉 **"점 K개를 전부 한 주파수에 몰아 놓는다면 어느 주파수여야 같은 정밀도가 나오는가"** 가 β다.

v0.1은 β를 "원점에서 평균 거리(지렛대)"라고 적었는데 두 군데가 어긋난다. 첫째, 단순 평균이 아니라 제곱 평균이라서 높은 주파수 쪽으로 치우친다(150~2000 Hz를 고르게 쓰면 단순 평균은 1075 Hz, β는 1194 Hz). 둘째, 지렛대는 점마다의 fₖ이고 β는 그 지렛대들을 대표하는 값 하나다. 그리고 β는 기울기(−2πτ)를 정하지 않는다. 기울기는 소리의 방향이 정하고, β·√K는 그 기울기를 **얼마나 정확히 읽는가**를 정한다.

**β만 따로 보면 판단을 그르친다.** 1000, 2000 Hz 두 점에 500 Hz 점을 더하면 β는 1581 → 1323 Hz로 내려가지만 β·√K는 2236 → 2291 Hz로 올라간다. 점을 더하면 합은 반드시 늘어난다. β는 평균이라서 낮은 점이 들어오면 내려갈 뿐이다.

| K를 늘리는 방법                      | K    | β         | β·√K      | 이유                                             |
| ------------------------------------ | ---- | --------- | --------- | ------------------------------------------------ |
| T를 늘림 (같은 대역에 점이 촘촘해짐) | 증가 | 그대로    | √배로 증가 | 평균 위치는 같고 개수만 늘어남                   |
| 대역을 위로 넓힘                     | 증가 | 증가      | 크게 증가 | 새로 들어오는 점의 f²가 큼                       |
| 대역을 아래로 넓힘                   | 증가 | 약간 감소 | 조금 증가 | 새 점의 f²가 작아 평균은 내려가지만 합은 늘어남  |

기여가 f²에 비례하므로 3000 Hz 점 하나(9.0×10⁶)가 100~1000 Hz의 점 열 개(합 3.85×10⁶)보다 크다. 단, 이 모든 것은 **그 칸에 실제로 신호가 있을 때**의 이야기다.

### 2.5 d는 시간을 각도로 바꾼다: σθ의 유도

여기까지 얻은 것은 시간의 흔들림 σ_τ이고, 원하는 것은 각도의 흔들림 σθ다. 둘을 잇는 것이 마이크 간격 d다.

**한 쌍.** 소리가 쌍의 정면에서 θ만큼 비껴 오면 먼 쪽 마이크까지 d·sinθ만큼 더 가야 한다. 음속으로 나누면 시간이고, θ로 미분하면 "각도가 조금 변할 때 τ가 얼마나 변하는가"가 나온다.

```
τ = d·sinθ / c     →     dτ/dθ = d·cosθ / c     →     σθ(한 쌍) = c / (d·cosθ) · σ_τ
```

τ(θ) 곡선이 가파를수록(d가 클수록, 정면일수록) 같은 시간 오차가 좁은 각도 범위가 된다. 옆에서 오는 소리는 곡선이 평평해져 한 쌍으로는 각도를 거의 알 수 없다.

**정삼각형 세 쌍.** 각 쌍은 방향 벡터 u(길이 1)를 자기 축에 비춘 값을 잰다. c·τᵢ = −aᵢ·u (aᵢ는 쌍을 잇는 벡터, 길이 d). 세 식을 최소제곱으로 풀면 û = (AᵀA)⁻¹Aᵀb다. 세 축이 60°씩 어긋나 있으면 cos²0° + cos²60° + cos²120° = 3/2이므로

```
AᵀA = (3d²/2)·I
û의 흔들림(x, y 각각) = c·σ_τ·√(2 / 3d²) = (c/d)·√(2/3)·σ_τ
```

u는 길이가 1인 화살표라서 끝이 옆으로 ε만큼 밀리면 각도가 ε 라디안 변한다. 그래서

```
σθ ≈ (c/d)·√(2/3)·σ_τ  [rad]          d = 14 cm, σ_τ = 5 µs → 2450 × 0.816 × 5×10⁻⁶ = 0.010 rad ≈ 0.57°
```

cosθ가 사라졌다. 한 쌍이 둔한 방향에서 다른 두 쌍이 민감해서 **어느 방향이든 같은 정밀도**가 된다. 세 쌍은 마이크를 공유하므로 "서로 독립"은 근사다.

| d | 최대 지연 d/c | (c/d)·√(2/3) | σ_τ 5 µs의 각도 오차 | c/2d |
| --- | --- | --- | --- | --- |
| 7 cm | 204 µs | 4001 /s | 1.15° | 2450 Hz |
| 14 cm | 408 µs | 2000 /s | 0.57° | 1225 Hz |
| 28 cm | 816 µs | 1000 /s | 0.29° | 612 Hz |

**d가 주는 것과 가져가는 것.** d를 2배로 하면 같은 σ_τ가 절반의 각도 오차가 된다. 대신 c/2d가 절반으로 내려간다. c/2d는 "지연이 최대(d/c)일 때 위상이 딱 반 바퀴 도는 주파수"이고, 그 위의 주파수는 가짜 봉우리를 만들 수 있다. 대역 상한을 c/2d 아래로 묶어 버리면 β와 K가 같이 줄어서 이득이 사라지는 정도가 아니라 **손해**가 된다(넓게 퍼진 소리, σφ 0.32 rad, 1024점 @ 50 kHz 기준으로 7 cm에 상한 2450 Hz일 때 1.14°, 14 cm에 상한 1225 Hz일 때 1.59°). 그래서 상한을 묶는 대신 고조파 마스크로 믿을 만한 칸만 고르는 쪽을 시험한다(E7).

> 주의: 문서상 d는 14 cm로 결정되어 있으나 현재 코드는 7 cm 기준이다(`TDOA_MAX_LAG 13`). c/2d 위의 주파수를 써도 되는지는 5.7절에서 따로 다룬다. 결론만 적으면, 고조파 음원에서 c/2d와 견줄 것은 가장 높은 주파수가 아니라 f0다.

### 2.6 요약: 지렛대는 두 단이다

```
위상 잡음 σφ  ──(÷ 2π·β·√K)──▶  시간 오차 σ_τ  ──(× (c/d)·√(2/3))──▶  각도 오차 σθ
```

β·√K는 주파수 축의 지렛대(위상 → 시간), d는 공간의 지렛대(시간 → 각도)다.

**이 식이 가정한 것.** 모든 점의 σφ가 같고 서로 독립이며, 올바른 봉우리를 골랐다는 것이다. 칸마다 믿을 만한 정도가 다르면 1/σ_τ² ∝ Σ(2πfₖ)²·SNRₖ로 바뀐다(칸의 기여 = 지렛대² × 신뢰도). 신호가 약해 σφ가 0.5 rad를 넘는 영역에서는 식이 말하는 흩어짐보다 엉뚱한 봉우리를 고르는 **튐**이 먼저 문제가 된다. 그리고 Step 3에서 봤듯이 실제 오차에는 반사처럼 이 식에 없는 원인도 있다. 식은 방향을 알려 주고, 값은 재서 확인한다.

## 3. 다이얼과 결과값

### 3.1 무엇을 돌리고 무엇이 따라 나오나

| 구분                   | 항목                                                                                                                         |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 직접 돌리는 다이얼     | N, 처리 속도 Fs(4절), d, 가중 방식(대역 또는 bin 마스크), 평균 시간(지수평균 시정수 또는 프레임 수 M), 창 함수, 신뢰 판정 임계값 |
| 다이얼이 정하는 결과값 | T = N/Fs, Δf = 1/T, S = Fs·d/c, K, β, σ_τ, σθ, 출력 지연, CPU 점유율 U                                                       |
| 다이얼이 아닌 입력값   | 대상 소리의 스펙트럼(f0, 에너지가 있는 고조파, 선의 폭), 배경 잡음. **재서 얻는 값**                                         |
| 지금은 다루지 않음     | 마이크 개수·배치 (성능 문제가 확인되기 전까지)                                                                               |

K와 β는 직접 고르지 않는다. 가중 방식, T, **대상 소리의 스펙트럼**이 정해지면 따라 나온다. 그래서 가장 먼저 할 일은 대상 소리의 f0와 고조파 구조를 재는 것이다(7절).

### 3.2 먼저 구분할 것: "시간" 네 가지

| 이름      | 뜻                                                                           |
| --------- | ---------------------------------------------------------------------------- |
| T         | 한 프레임에 **담긴 소리의 길이** (관측 시간). 처리 시간이 아니다              |
| 처리 시간 | 그 프레임을 CPU가 **계산하는 데 걸리는 시간**                                |
| τ         | 두 마이크에 소리가 **도달하는 시각의 차이**. 재려는 값. 최대 d/c             |
| 출력 지연 | 소리가 난 뒤 결과가 나오기까지 ≈ T + 처리 시간 (평균을 쓰면 시정수만큼 추가) |

T를 늘려서 커지는 것은 출력 지연이지 τ가 아니다. 각도 오차는 줄어든다. 움직이는 표적만 T 동안 평균되어 번진다.

### 3.3 T를 늘리면 무엇이 좋아지나: 소리의 종류에 따라 길이 다르다

| | 넓게 퍼진 소리 | 고조파 (드론) |
| --- | --- | --- |
| T를 2배로 하면 | 같은 대역 안에 신호가 있는 bin이 2배 → **K가 2배** | 선의 개수는 그대로라 K는 그대로. 대신 bin이 좁아져 잡음이 절반만 들어옴 → **선 bin의 SNR이 2배** |
| 움직이는 단 | β·√K | σφ |
| 결과 | σ_τ가 1/√2배 | σ_τ가 1/√2배. 단, 선의 폭이 bin보다 좁을 때까지만 |

v0.1의 "T를 늘리면 K 증가"는 넓게 퍼진 소리 기준이었다. 드론에서는 K가 늘지 않고 선이 잡음 위로 올라온다.

T를 얻는 방법은 둘이다. N을 늘리면(Fs 고정) 처리 시간이 N·log₂N으로 늘고, Fs를 낮추면(N 고정) 처리 시간은 그대로다. N을 늘려서 시간 여유를 살 수는 없다. 프레임당 남는 시간은 늘지만 초당 남는 시간은 늘지 않는다.

### 3.4 어느 다이얼이 어느 단을 움직이나

| 다이얼 | 움직이는 단 | 얼마나 | 대가 |
| --- | --- | --- | --- |
| 평균 α를 낮춤 (프레임을 더 많이 겹침) | σφ | 1/√(유효 프레임 수), 유효 프레임 수 ≈ 2/α − 1 | 시정수 T/α만큼 늦게 따라감. 움직이는 표적이 번짐 |
| T를 늘림 | σφ 또는 β·√K (3.3절) | 1/√T | 출력 지연 |
| 대역·마스크의 상한을 올림 | β와 K | Σf²가 늘어난 만큼 | 신호 없는 bin이 들어오면 손해. c/2d 위는 가짜 봉우리 위험 |
| d를 키움 | c/d | 1/d | c/2d가 내려감. 기구가 커짐 |
| 창 함수, 신뢰 판정 임계값 | 식에 없음 | — | 흩어짐이 아니라 **튐**을 다룬다. 임계값을 조이면 쓸 수 있는 결과의 비율이 줄어듦 |

평균하는 대상은 각도나 X[k]가 아니라 **교차 스펙트럼 G[k] = X₂[k]·conj(X₁[k])** 다. X[k]의 위상은 프레임마다 바뀌지만 G[k]의 위상은 유지된다. 신호의 화살표는 매 프레임 같은 방향이라 M배로 쌓이고, 잡음의 화살표는 방향이 제각각이라 √M배로만 쌓인다.

신뢰 판정 임계값은 **결과 단위**로 거르는 기준이다(peak, norm, 세 쌍 일치, 직전 각도 대비 점프). bin 단위로 위상 직선에서 벗어난 점을 빼는 방식은 쓰지 않는다. 고조파 마스크가 같은 일을 τ와 무관한 기준으로 먼저 하기 때문이다.

### 3.5 튜닝하는 순서

1. **대상 소리를 먼저 잰다.** f0, 에너지가 있는 고조파의 범위, 선의 폭은 다이얼이 아니라 주어지는 값이다.
2. **식으로 탈락시킨다.** f0/Δf(5.2절), c/2d, S, U는 실험 없이 계산된다. 조건을 못 넘는 조합은 보드에 올리기 전에 버린다.
3. **기준선을 고정하고 하나씩 바꾼다.** 원파형 덤프를 PC에서 다이얼만 바꿔 다시 계산한다.
4. **숫자 두 개를 따로 본다.** 흩어짐(정상 결과의 RMS)은 2절의 식이 예측한다. 튐 비율은 식이 예측하지 못한다. 약한 신호에서는 튐이 먼저 무너진다.
5. **식과 실측이 다르면 실측이 맞다.** Step 3에서 이론은 높은 대역이 유리하다고 했지만 실제 스냅은 반대였다.

## 4. 처리 속도와 FIR 필터: 왜 50 kHz로 재고 12.5 kHz로 처리하나

### 4.1 결론

**ADC는 50 kHz 그대로 두고, 세 채널에 같은 저역 FIR 필터를 건 뒤 네 샘플마다 하나씩만 남겨 12.5 kHz로 만든다(데시메이션). 이후의 처리는 모두 12.5 kHz에서 한다.** 타이머를 12.5 kHz로 내려 ADC가 직접 그 속도로 재게 하는 방식은 쓰지 않는다.

출발점이 된 생각은 옳다. 정밀도를 정하는 것은 쓰는 대역(β·√K)과 SNR이지 Fs가 아니다. 우리가 쓰는 주파수는 수 kHz 이하이고, 12.5 kHz로 처리하면 같은 N으로 4배 긴 T를 얻는다(2048점이면 164 ms, Δf 6.1 Hz). 틀린 부분은 "그러니 ADC를 12.5 kHz로 돌리면 된다"는 한 걸음이다.

### 4.2 타이머를 내리면 안 되는 이유: 접힘은 한번 일어나면 되돌릴 수 없다

샘플링 조건은 "Fs ≥ 2 × 내가 쓸 최고 주파수"가 아니라 **"Fs ≥ 2 × ADC 핀에 실제로 들어오는 최고 주파수"** 다. 파형을 복원할 것인지와는 관계가 없다. 샘플만 보고는 Fs/2보다 높은 성분과 그것이 접힌 낮은 성분을 구분할 수 없기 때문이다.

12.5 kHz로 재면 접히는 자리가 정해져 있다. 우리가 0~f_use를 쓴다면 다음 대역의 소리가 그 안으로 들어온다.

```
12.5 kHz − f_use  ~  12.5 kHz + f_use        (f_use = 2.5 kHz라면 10~15 kHz)
25 kHz − f_use    ~  25 kHz + f_use          (22.5~27.5 kHz)
```

10~15 kHz는 마이크와 앰프가 그대로 통과시키는 대역이다. 그 대역의 소리(다른 방향의 고음, 드론 자체의 고주파 성분, 앰프 잡음)가 1 kHz 근처의 것으로 둔갑해 들어오고, **들어온 뒤에는 어떤 디지털 필터로도 골라낼 수 없다.** 지금 코드의 BPF(대역 밖 bin을 0으로 만들기)도 FFT 뒤의 일이라 소용이 없다. 접힌 성분은 이미 대역 안의 bin에 섞여 있다.

50 kHz로 잴 때는 같은 문제가 47.5~52.5 kHz에서 생기는데, 그 대역은 마이크와 앰프가 이미 깎아 낸 뒤다. 50 kHz라는 값의 진짜 쓸모가 이것이다. 가청 대역을 담으려는 것이 아니라 **접힘이 일어나는 자리를 소리가 없는 곳으로 밀어 올리는 것**이다.

### 4.3 FIR 필터가 하는 일

샘플을 버리는 순간이 곧 다시 샘플링하는 순간이다. 50 kHz 신호에서 네 개 중 하나만 남기면 그 자리에서 12.5 kHz의 접힘이 일어난다. 그래서 **버리기 전에, 아직 구분할 수 있을 때, 접힐 대역을 지운다.** 그것이 FIR 저역 필터다. 순서가 핵심이다.

```
[50 kHz 샘플]  →  [저역 FIR: 접힐 대역을 지움]  →  [4개 중 1개만 남김]  →  [12.5 kHz 샘플]
```

**필터에 요구되는 것**은 두 가지뿐이다.

- 통과 대역: 0 ~ f_use는 그대로 둔다.
- 저지 대역: 12.5 kHz − f_use 위로는 충분히 깎는다(예: 60 dB).

그 사이(f_use ~ 12.5 kHz − f_use)는 신경 쓰지 않아도 된다. 그 대역의 소리는 접혀도 f_use 위의, 우리가 쓰지 않는 bin에 떨어지기 때문이다. 이 덕분에 필터가 가벼워진다. 실제로 설계해 본 탭 수는 아래와 같다(50 kHz, 저지 60 dB, Kaiser 창).

| 쓸 대역 f_use | 저지 대역 시작 | 탭 수 | 군지연 | 3채널 곱셈·덧셈 횟수 |
| --- | --- | --- | --- | --- |
| 2.5 kHz | 10 kHz | 27 | 0.26 ms | 초당 101만 |
| 5 kHz | 7.5 kHz | 75 | 0.74 ms | 초당 281만 |
| 6 kHz | 6.5 kHz | 365 | 3.64 ms | 초당 1369만 |

쓸 대역을 Fs/2(6.25 kHz)에 바짝 붙일수록 탭 수가 급격히 늘어난다. **f_use를 얼마로 잡느냐가 곧 필터의 값이고, 그것은 대상 소리의 고조파가 어디까지 있느냐로 정해진다**(7절). 계산량은 180 MHz 코어에 부담이 아니다. 남길 샘플의 출력만 계산하면 되므로(데시메이션 FIR, CMSIS-DSP의 `arm_fir_decimate_f32`) 위 표는 이미 4분의 1로 줄어든 값이다.

**덤으로 얻는 것: 잡음.** 앰프 잡음은 0~25 kHz에 고르게 퍼져 있다. 직접 12.5 kHz로 재면 네 구간의 잡음이 한 구간으로 겹쳐 들어온다. 필터를 거치면 세 구간의 잡음이 먼저 지워진다. 약 6 dB 차이이고, 멀리 있는 약한 드론에서는 이것이 탐지 거리다.

### 4.4 이 필터가 방향 추정을 망치지 않는 이유와 조건

필터는 신호를 늦추고 위상을 바꾼다. 그런데도 τ가 보존되는 이유는 **세 채널에 완전히 같은 필터를 쓰기 때문**이다. 필터의 응답을 H라 하면 교차 스펙트럼은 (H·X₂)·conj(H·X₁) = |H|²·X₂·conj(X₁)이 되어 필터의 위상이 상쇄된다. 남는 |H|²는 크기일 뿐이고 PHAT이 지운다. 통과 대역이 조금 울퉁불퉁해도 방향에는 영향이 없다는 뜻이기도 하다.

지켜야 할 조건이 세 가지 있고, 어기면 눈에 띄는 증상으로 나타난다.

| 조건 | 어기면 | 크기 |
| --- | --- | --- |
| 세 채널의 계수가 같다 | 채널 사이에 주파수마다 다른 위상 차이 → 각도 치우침 | 계수 차이에 비례 |
| 세 채널이 **같은 번째 샘플**을 남긴다 (4개 중 몇 번째인가) | 채널 사이에 20, 40, 60 µs의 고정 지연 | 20 µs 하나가 14 cm 기준 약 2.3° |
| 필터의 상태(직전 샘플들)를 DMA 버퍼 경계에서 **지우지 않고 이어 간다** | 20.48 ms마다 필터가 새로 시작하며 과도 응답이 생김 → 48.8 Hz 간격의 빗 모양 | **고조파 검출기가 이것을 드론으로 본다** |

세 번째가 가장 조심할 곳이다. 반버퍼(1024샘플)마다 필터를 초기화하면 일정한 간격으로 되풀이되는 흠이 생기고, 되풀이되는 것은 5절의 원리 그대로 정수배 선으로 나타난다. 검출기가 찾는 바로 그 모양이다.

### 4.5 다른 방법과 비교

| 방법 | 판정 | 이유 |
| --- | --- | --- |
| ADC 타이머를 12.5 kHz로 | 버림 | 10~15 kHz가 접혀 들어옴. 잡음 약 6 dB 손해 (4.2절) |
| 아날로그 필터를 6 kHz에 | 버림 | 6 kHz는 통과, 7.5 kHz는 60 dB 차단하는 기울기를 RC 몇 단으로는 만들 수 없음. 채널마다 부품 오차로 위상이 달라져 방향이 치우침 |
| 4샘플 평균 후 버리기 | 버림 | 가장 싸지만 10 kHz에서 −12 dB, 11 kHz에서 −17 dB밖에 못 깎음 |
| 필터 없이 50 kHz로 8192점 FFT | 버림 | 같은 T와 Δf를 얻고 접힘도 없지만 FFT 버퍼만 3채널에 98 KB. F446RE의 RAM은 128 KB |
| **저역 FIR + ↓4** | **선택** | 접힘 제거, 잡음 이득, 세 채널이 수학적으로 같은 필터, 계산량 작음 |

아날로그 필터가 필요 없어지는 것은 아니다. 50 kHz에서의 접힘(25 kHz 위)은 여전히 아날로그 쪽의 일이다. 포탑 모터의 PWM이 25 kHz 근처라면 이쪽에서 문제가 된다(E9).

### 4.6 시뮬레이션으로 확인한 것

마이크 한 쌍, d = 14 cm, f0 200 Hz의 고조파 음원, 프레임 164 ms로 지연 추정 오차를 비교했다. 각도는 정삼각형 세 쌍 기준 환산이다. `계산`이 아니라 `시뮬레이션` 근거다.

| 조건 | 50 kHz | 12.5 kHz (FIR 후 ↓4) | 12.5 kHz (ADC 직접) |
| --- | --- | --- | --- |
| 잡음 없음 (지연 눈금이 거친 영향만) | 0.01° | 0.07° | 0.07° |
| 넓은 대역 잡음, SNR 0 dB | 0.70° | 0.71° | **1.24°** |
| 11.5 kHz 음이 섞임 (접히면 5번째 고조파 칸) | 0.01° | 0.07° | **0.97°** |
| 10.5 kHz 음이 섞임 (접히면 10번째 고조파 칸) | 0.01° | 0.07° | **1.98°** |
| 11.0 kHz 음이 섞임 (접히면 고조파 사이) | 0.01° | 0.07° | 0.07° |

- **지연 눈금 S는 제약이 아니었다.** 최대 지연이 20.4샘플에서 5.1샘플로 줄어도 오차는 0.07°이고, IFFT 크기를 4배로 늘려 보간하면 50 kHz와 같아진다. v0.1의 "방향 경로는 Fs를 20 kHz 아래로 내리지 않는다"는 제약을 푼다.
- **FIR을 거치면 50 kHz와 같다**(0.70° 대 0.71°). 직접 재면 잡음이 겹쳐 약 1.75배가 된다.
- 섞은 음의 주파수는 고조파 칸에 정확히 떨어지도록 고른 최악 조건이다. 고조파 사이에 떨어지면 마스크가 버린다.

이 시뮬레이션에는 반사, 마이크 특성 차이, f0의 흔들림이 없다. 실제 값은 연속 덤프로 50 kHz 기준선과 비교해 확인한다(11절 4-0).

## 5. 고조파 검출기 설계

### 5.1 드론 소리는 왜 빗 모양인가

프로펠러 날개가 한 번 지나갈 때마다 공기를 한 번 친다. 같은 모양의 압력 변화가 일정한 간격으로 되풀이되고, 1초에 되풀이되는 횟수가 기본 주파수 f0다. **똑같이 되풀이되는 파형은 f0의 정수배 사인파만으로 만들어진다.** 정수배가 아닌 사인파는 한 주기 뒤에 제자리로 돌아오지 않아서, 섞이면 다음 주기의 모양이 달라지기 때문이다.

여기서 세 가지가 나온다.

- 스펙트럼에서 에너지는 f0, 2·f0, 3·f0 … 자리에만 있고 그 사이는 비어 있다. 이 **빗 모양**이 드론과 바람·빗소리(넓게 퍼짐)를 가른다. "소리가 큰가"가 아니라 "빗 모양인가"를 본다.
- 선 사이의 간격이 곧 f0다. f0만 알면 나머지 선의 자리를 모두 안다. 검출기는 f0 하나를 찾는 문제가 된다.
- 한 번 치는 폭이 좁을수록 높은 고조파까지 에너지가 있다. 몇 번째까지 쓸 만한지는 기종마다 다르고 재 봐야 안다.

실제 드론은 로터 여러 개가 조금씩 다른 속도로 돌아서 높은 고조파일수록 선이 퍼지거나 갈라진다. f0는 날개 수 × 초당 회전수이고, 회전수가 바뀌면 빗 전체가 같은 비율로 늘거나 준다.

### 5.2 왜 f0/Δf부터 보나

검출기가 보는 것은 FFT가 내놓는 칸별 에너지뿐이다. 칸의 폭이 Δf = 1/T, 빗살 사이의 간격이 f0다. 그러면 **f0/Δf는 빗살과 빗살 사이에 칸이 몇 개 들어가는가**다. 이 값이 1~2이면 모든 칸에 빗살이 하나씩 들어가서 스펙트럼이 평평해 보이고 빗 모양 자체가 사라진다. 눈금이 1 cm인 자로 5 mm 간격의 줄무늬를 재려는 것과 같다.

같은 값을 다르게 읽으면 뜻이 더 분명해진다. f0/Δf = f0 × T, 즉 **프레임 하나에 담긴 기본 주기의 개수**다. 되풀이되는 모양을 알아보려면 적어도 3~4번은 봐야 한다. 5 ms 프레임에 100 Hz 소리는 반 주기뿐이다.

- **왜 3인가 (Hann 창이면 4).** 빗살 하나는 칸의 한가운데에 떨어지지 않으면 이웃 칸까지 1~2칸을 차지한다. Hann 창을 쓰면 3~4칸이다. 그 옆에 빈 칸이 적어도 하나는 있어야 대비가 생긴다.
- **못 넘으면.** 탐지에서는 점수 S(f0)가 드론과 넓게 퍼진 소음을 구분하지 못한다. 방향 추정에서는 마스크가 거의 모든 bin을 덮어서 지금의 BPF + PHAT과 같아진다. 무너지지는 않지만 마스크를 만든 보람이 없다.
- **크면 클수록 좋은가.** 칸이 좁아질수록 한 칸에 들어오는 잡음이 줄어 선이 잡음 위로 올라온다(T가 8배면 약 9 dB). 하지만 T가 길면 반응이 늦고, 그동안 f0가 변하면 선이 번져 이득이 멈춘다.
- **왜 가장 먼저인가.** 실험 없이 f0와 T만으로 계산되고, 검출기의 다른 모든 결정이 "빗이 보인다"를 전제로 하기 때문이다.

| 처리 방식 | T | Δf | f0 100 Hz | 200 Hz | 300 Hz | 500 Hz |
| --- | --- | --- | --- | --- | --- | --- |
| 현재 스냅 코드 (250샘플 @ 50 kHz) | 5 ms | 200 Hz | 0.5 | 1 | 1.5 | 2.5 |
| 50 kHz, 1024점 | 20.48 ms | 48.8 Hz | 2.0 | 4.1 | 6.1 | 10 |
| 12.5 kHz, 512점 | 41 ms | 24.4 Hz | 4.1 | 8.2 | 12 | 20 |
| 12.5 kHz, 1024점 | 82 ms | 12.2 Hz | 8.2 | 16 | 25 | 41 |
| 12.5 kHz, 2048점 | 164 ms | 6.1 Hz | 16 | 33 | 49 | 82 |

f0가 높은 대상일수록 짧은 프레임으로도 조건을 넘는다. FPV형의 f0가 수백 Hz라면 f0/Δf는 더 이상 N을 정하는 제약이 아니고, N은 필요한 SNR과 반응 시간 사이에서 정해진다(7절).

### 5.3 고조파 점수 S(f0)

f0를 모르니 후보를 하나씩 넣어 본다. 후보 f0의 1배, 2배 … H배 자리에 빗살을 세우고, 각 빗살이 닿은 칸이 잡음 바닥보다 얼마나 높은지를 더한다. 진짜 f0에서는 모든 빗살이 선에 걸려 점수가 높고, 틀린 f0에서는 대부분 빈 칸에 떨어진다.

```
S(f0) = Σ_{h=1…H} min( SNR(h·f0), 상한 )          SNR(f) = 그 칸의 세기 ÷ 그 칸의 평소 잡음 바닥
```

식의 각 부분에는 막으려는 실패가 하나씩 있다.

| 요소 | 없으면 생기는 일 |
| --- | --- |
| **잡음 바닥으로 나누기** | 바람은 낮은 주파수에서 매우 크다. 세기를 그대로 더하면 낮은 쪽 칸이 점수를 독차지해서, 드론이 없어도 낮은 f0 후보의 점수가 높게 나온다 |
| **상한** | 사이렌 같은 강한 음 하나가 그 음을 정수배로 갖는 모든 후보(1000 Hz라면 100, 125, 200, 250 Hz …)의 점수를 한꺼번에 올린다. 상한이 있으면 한 칸이 아무리 커도 한 표이고, **여러 빗살이 함께 걸려야** 점수가 높아진다 |
| **빗살 개수 H** | 너무 적으면 우연히 걸리는 경우와 구분이 안 된다. 너무 많으면 에너지가 없는 높은 고조파 자리에서 잡음만 더한다. 대상 소리에서 실제로 에너지가 있는 고조파 수에 맞춘다 |
| **후보의 간격** | H번째 빗살은 후보가 1 Hz 어긋나면 H Hz 어긋난다. 후보 간격 × H가 Δf를 넘으면 높은 빗살이 선을 지나친다. 간격을 Δf/H로 잡거나 빗살마다 ±1칸을 허용한다 |

잡음 바닥은 검출되지 않은 프레임에서만 칸별 지수평균으로 갱신한다. 검출 중이거나 모터 구동 중에 갱신하면 드론 소리를 바닥으로 배워서 점점 못 보게 된다.

**이 검출기가 묻는 것은 "잡음 바닥 위로 올라온 칸들이 같은 간격으로 늘어서 있는가"다.** 큰 소리 하나, 넓게 퍼진 소음, 낮은 주파수의 바람은 이 질문에서 걸러진다. 반대로 빗 모양을 가진 소리는 드론이 아니어도 통과한다. 공개 영상의 소리에 이 점수를 돌려 보니 가장 높은 점수가 나온 구간은 해설자의 목소리와 인트로 음악이었다(7.2절). 그것을 가르는 일은 f0가 머무는 범위, 지속 시간, 운동 일관성, 카메라의 몫이다.

### 5.4 알려진 약점: 절반과 두 배

점수 곡선에는 진짜 f0 말고도 봉우리가 있다. 후보가 f0/2이면 짝수 번째 빗살이 모두 진짜 선에 걸리고(점수 약 절반), 후보가 2·f0이면 모든 빗살이 진짜 선의 짝수 번째에 걸린다. 높은 고조파까지 강한 소리에서는 2·f0의 점수가 f0와 같아져서 어느 쪽이 뽑힐지 알 수 없다.

| 틀리는 방향 | 탐지에 미치는 영향 | 방향 마스크에 미치는 영향 | 대응 |
| --- | --- | --- | --- |
| 2·f0로 읽음 | 거의 없음 (점수는 높음) | 선의 절반만 씀 → 정밀도 손해, 틀리지는 않음 | 점수가 최댓값의 90% 이상인 후보 중 **가장 낮은 f0**를 고름 |
| f0/2로 읽음 | 점수가 절반이라 보통 뽑히지 않음 | 빗살의 절반이 빈 칸 → 잡음 bin이 섞임 | 위 규칙에서 걸러짐 |
| 프레임마다 오락가락 | M-of-N이 흔들림 | 마스크가 프레임마다 바뀜 | f0 추적: 직전 f0 근처만 탐색 |

"가장 낮은 f0" 규칙은 합성 신호에서는 통했지만(`Tools/audio/f0_probe.py`, 117·210·95 Hz) 실제 녹음에서는 낮은 주파수의 잡다한 선에 끌려가는 것이 보였다. 후보 범위의 하한을 대상에 맞게 올려야 한다.

### 5.5 임계값과 M-of-N: 미탐과 오탐

점수가 얼마 이상이면 드론이라고 할지는 감으로 정하지 않는다. 드론이 없을 때의 점수와 있을 때의 점수를 각각 많이 모아 분포를 그리고, 임계값을 움직여 오탐과 미탐이 맞바뀌는 것을 본다(ROC).

|           | 미탐                  | 오탐                                                                                       |
| --------- | --------------------- | ------------------------------------------------------------------------------------------ |
| 직접 피해 | 대피 실패 → 인명 피해 | 불필요한 경보, 포탑 회전                                                                   |
| 간접 피해 |                       | 회전 중(약 0.65 s) 음향 먹통, 다른 방향 감시 공백, 경보 피로로 시스템을 끔 → **결국 미탐** |

1. **두 분포를 모은다.** 배경 잡음 덤프(조용할 때, 바람, 모터 구동 중)와 드론 소리 덤프에 같은 검출기를 돌린다.
2. **오탐의 허용치를 먼저 정한다.** "시간당 몇 번까지"는 운용자가 정하는 요구사항이다. 그 값에서 임계값이 정해지고 탐지 확률은 결과로 읽는다. 순서가 반대가 아니다.
3. **M-of-N으로 묶는다.** 1차는 임계값을 낮춰 놓치지 않게 하고, "연속 N구간 중 M구간 이상"으로 오탐을 걸러 낸다. 우연한 오탐은 연달아 일어나기 어렵다.
4. **대가는 시간이다.** 확정까지 N구간을 기다린다. 반응 시간 예산 안에서 M, N, 구간 길이를 정한다.

| 3-of-5 확정 적용 | 구간당 | 확정 후 |
| ---------------- | ------ | ------- |
| 오탐             | 10⁻²   | 약 10⁻⁵ |
| 탐지             | 0.70   | 0.84    |

잡음 프레임이 400개뿐이면 오탐 확률은 1/400보다 작은 값을 잴 수 없다. 목표가 10⁻⁴이면 수만 개가 필요하다. 4-2에서 배경 잡음을 많이 모으는 이유다. 또 M-of-N 계산은 구간끼리 독립이라고 가정한다. 돌풍처럼 몇 초씩 이어지는 잡음은 연달아 오탐을 내므로 실제 값은 덤프로 확인한다.

### 5.6 설계 순서

위에서부터 차례로 정한다. 앞 단계의 답이 뒤 단계의 입력이다.

| 순서 | 정할 것 | 무엇을 보고 | 기준 | 틀리면 보이는 증상 |
| --- | --- | --- | --- | --- |
| 0 | 대상 소리의 성질 | 녹음의 스펙트로그램 | f0의 범위, 에너지가 있는 고조파 수, 선의 폭, f0가 변하는 속도 | 이후의 모든 숫자에 근거가 없음 |
| 1 | Δf (= 1/T) | 가장 낮은 f0 | f0/Δf ≥ 3 (Hann이면 4). 선의 폭보다 좁게 잡아도 이득 없음. T는 반응 시간 예산 안 | 빗이 안 보임 |
| 2 | 처리 속도와 FIR | 가장 높은 f0 × H | 그 값이 f_use. 처리 속도의 절반보다 낮아야 하고, FIR의 탭 수가 여기서 정해짐 (4.3절) | 높은 빗살이 범위 밖이거나 접힘 |
| 3 | 잡음 바닥 | 검출되지 않은 프레임 | 칸별 지수평균. 검출 중·모터 구동 중에는 갱신 중지 | 드론을 바닥으로 배움 |
| 4 | 점수 식 | 0번의 고조파 수 | H, 상한, 후보 간격 × H ≲ Δf | 단일음·바람에 반응 |
| 5 | 임계값 | 두 점수 분포 | 오탐 허용치 → 임계값 → 탐지 확률 | 오탐이 많거나 가까이 와야 잡힘 |
| 6 | M-of-N | 반응 시간 예산 | 초기안 3-of-5 | 확정이 늦거나 오탐이 통과 |
| 7 | f0 추적 | 0번의 변화 속도 | 직전 f0 근처만 탐색 | f0가 프레임마다 튐 |
| 8 | 방향 추정의 마스크 | 7번의 f0, 0번의 선 폭 | h·f0 자리의 bin만 무게 1. 폭 = max(1 bin, 0.03·h·f0)에서 시작 | BPF + PHAT보다 나아지지 않음 |

### 5.7 고조파를 c/2d 위까지 써도 되는가

f0가 555 Hz라면 c/2d(7 cm에서 2450 Hz) 아래의 선은 555, 1110, 1665, 2220 Hz의 4개뿐이다. 14 cm(1225 Hz)면 2개다. 이것만 써야 한다면 표가 너무 적다. 그런데 c/2d는 "그 위의 주파수를 쓰면 안 된다"는 뜻이 아니다. **"그 주파수 하나만으로는 답을 하나로 정할 수 없다"** 는 뜻이다. 두 가지를 나눠서 본다.

**먼저, 탐지에는 c/2d가 없다.** c/2d는 마이크 두 개 사이의 위상 차이로 방향을 정할 때의 이야기다. 고조파 점수 S(f0)는 한 채널의 칸별 세기만 보므로 마이크 간격과 무관하다. 12.5 kHz로 처리하면 6.25 kHz까지, 555 Hz의 11번째 고조파까지 탐지에 쓴다.

**방향 추정에서 c/2d가 어디서 나오는지**를 다섯 걸음으로 따라간다.

**(1) 주파수 하나가 아는 것은 "한 바퀴 안에서 어디인가"뿐이다.** 위상은 한 바퀴 돌면 같은 값으로 돌아온다. 그래서 지연이 τ일 때와 τ에서 한 주기(1/f)만큼 떨어졌을 때의 위상이 똑같고, 그 주파수는 둘을 구분하지 못한다. 시계에서 분침만 보는 것과 같다. "20분"인 것은 알지만 몇 시인지는 모른다. 후보는 1/f 간격으로 끝없이 늘어서 있다.

**(2) 물리가 범위를 준다.** 지연은 마이크 사이를 소리가 지나는 시간을 넘을 수 없으므로 −d/c부터 +d/c까지, 폭 2d/c 안에 있다(탐색 범위). 후보의 간격 1/f가 이 폭보다 길면 범위 안에 후보가 하나만 들어가서 답이 정해진다.

```
1/f > 2d/c     ⇔     f < c/2d          c/2d가 나오는 곳은 여기 한 군데다
```

**(3) c/2d보다 높은 주파수는 범위 안에 후보가 둘 이상이다.** 틀린 말을 하는 것이 아니라 "이 둘 중 하나"라고 말하는 것이고, 혼자서는 어느 쪽인지 모를 뿐이다. f0 555 Hz, d 7 cm(탐색 범위 ±204 µs), 실제 지연 +180 µs인 경우를 적어 보면 이렇다.

| 선 | 후보 간격 1/f | 범위 안에 드는 후보 | 혼자서 정할 수 있나 |
| --- | --- | --- | --- |
| 555 Hz (1번째) | 1802 µs | +180 | 예 |
| 1110 Hz (2번째) | 901 µs | +180 | 예 |
| 2775 Hz (5번째) | 360 µs | +180, −180 | 아니오 |
| 5550 Hz (10번째) | 180 µs | +180, 0, −180 | 아니오 |

**(4) 여러 주파수가 함께 투표하면 진짜만 남는다.** 네 줄 모두에 들어 있는 후보는 +180 µs 하나다. 가짜 후보는 주파수마다 간격이 달라서 자리가 엇갈린다. 2775 Hz의 가짜 자리(−180 µs)에서 555 Hz 선은 360 ÷ 1802 = 0.2바퀴(72°) 어긋나 있어서 그 자리에 표를 주지 않는다. 낮은 주파수가 **"어느 후보인가"** 를 정하고, 높은 주파수가 **"정확히 어디인가"** 를 정한다. 시침과 분침을 함께 보는 것이다. GCC-PHAT이 화살표를 모두 더하는 것이 바로 이 투표다(2.2절).

**(5) 모든 선이 다시 한 번 겹치는 곳은 1/f0 떨어진 곳이다.** 고조파는 f0의 정수배라서 h번째 선의 후보 간격은 (1/f0)을 h로 나눈 값이다. 전부 1/f0의 약수이므로, 1/f0만큼 떨어진 곳에서 처음으로 모든 선이 다시 겹친다. 그 간격이 탐색 범위의 폭보다 길면 범위 안에는 진짜 하나뿐이다.

```
1/f0 > 2d/c     ⇔     f0 < c/2d
```

| | 탐색 범위의 폭 2d/c | 다시 겹치는 간격 1/f0 (555 Hz) | 진짜와 같은 높이의 가짜가 범위 안에 드는가 |
| --- | --- | --- | --- |
| 7 cm | 408 µs | 1802 µs | 아니오 |
| 14 cm | 816 µs | 1802 µs | 아니오 |
| 31 cm 이상 | 1808 µs 이상 | 1802 µs | 예 |

**결론: 고조파 음원에서 c/2d와 견줄 것은 "쓰는 가장 높은 주파수"가 아니라 "선과 선 사이의 간격 f0"다.** 기본음부터 연달아 있는 고조파라면 c/2d 위의 선을 써도 진짜와 같은 높이의 가짜 봉우리는 생기지 않는다. 그리고 선을 많이 쓸수록 두 가지가 좋아진다.

- **정밀도.** Σh²가 1~4번째면 30, 1~10번째면 385다. 모든 선의 σφ가 같다면 σ_τ가 √(385/30) ≈ 3.6배 좋아진다.
- **튐.** PHAT은 선마다 한 표다. 표가 4개면 잡음에 쉽게 뒤집히고, 10개면 덜 뒤집힌다.

남는 것은 진짜 봉우리 옆의 작은 곁봉우리다. 진짜와 같은 높이는 아니지만 잡음이 크면 이것이 뽑힐 수 있다.

| 쓰는 선 | 곁봉우리의 높이 (진짜 대비, 잡음 없음) | 뜻 |
| --- | --- | --- |
| 1~4번째 | 약 4% | 여유 있음. 다만 표가 적다 |
| 1~10번째 | 약 9% | 여유 있음 |
| 5~10번째 (낮은 선이 묻힘) | 약 25~30% | 잡음이 크면 뒤집힐 수 있음 |
| 5번째 하나만 | 100% | 구분 불가. Step 3의 "2450 Hz 위의 음조" 경우 |

위 표는 `손계산`이다(같은 크기의 선을 더한 식에서 직접 구함). 시뮬레이션과 실측으로는 아직 확인하지 않았다. 도우미 11절의 그림이 같은 계산을 브라우저에서 하므로 거기서 값을 바꿔 가며 볼 수 있다. 그림은 탐색 범위 안만 세므로, 곁봉우리가 범위 밖에 있을 때는 표보다 작게 나온다(7 cm에서 1~4번째를 쓰면 곁봉우리가 범위 밖이라 0%).

**이 논리가 깨지는 경우.** 이 때문에 실제 소리로 하는 검증(E7, 구현 단계 4-5)이 여전히 필요하다.

| 경우 | 무슨 일이 생기나 |
| --- | --- |
| 낮은 선이 없다 | 바람이나 차량 소음에 기본음 쪽이 묻히면 "어느 후보인가"를 정해 줄 선이 없어 곁봉우리가 커진다 (위 표의 셋째 줄) |
| f0를 두 배로 읽었다 | 마스크가 짝수 번째만 고르면 다시 겹치는 간격이 절반이 된다. 555 Hz면 901 µs이고 14 cm의 816 µs와 거의 붙는다 |
| 로터마다 f0가 다르다 | 빗이 네 벌 겹친다. 높은 고조파일수록 선이 갈라져 한 줄로 서지 않는다 |
| 반사 | 이 계산에 들어 있지 않다. 반사음은 다른 지연에 자기 봉우리를 만든다 |
| f0가 c/2d를 넘는다 | 조건 자체가 깨진다. 14 cm에서 f0 1225 Hz 이상 |

**d에 대한 뜻.** v0.2 초안은 "FPV형은 에너지가 c/2d 위에 있으니 d를 줄이는 쪽을 따져야 한다"고 적었는데, 위 내용에 따르면 맞지 않는다. f0가 수백 Hz인 한 14 cm도 조건(f0 < 1225 Hz)을 넘고, 간격이 넓은 쪽이 2.5절의 c/d에서 유리하다. d를 줄일 이유는 낮은 선이 자주 묻힌다는 것이 실측으로 확인될 때 생긴다.

## 6. 목표 파이프라인

```
ADC 3ch 50 kHz (동시 변환, DMA 반버퍼 1024샘플) ──────────── 건드리지 않음
   │
   ├─ [TRANSIENT 모드] 50 kHz 원본으로 기존 스냅 처리 (보정·시험용)
   │
   └─ [HARMONIC 모드]
        [저역 FIR + ↓4, 3채널 동일, 상태 유지] → 12.5 kHz (반버퍼당 256샘플)
           → 링버퍼에서 N샘플 창, 일정 간격으로 이동           N, 이동 간격은 7절 뒤에 확정
           → Hann → FFT ×3
               ├─ [S1 잡음 바닥] → [S2 고조파 점수 → f0] → [S3 M-of-N 확정]
               │                         │ f0, 고조파 bin
               │                         ▼
               └─ 교차 스펙트럼 → [S4 고조파 마스크 PHAT] → IFFT(보간) → LSE → 방위
           → [S5 출력 tdoa_meas_t] + [S6 재밍·기능저하 감지]
                                          ▼  UART
                     젯슨: 다중 트랙, 큐 우선순위, 카메라 확인 (S7)
```

v0.1은 탐지(12.5 kHz)와 방향(50 kHz)을 따로 두었다. 방향 쪽을 50 kHz로 남긴 근거가 지연 눈금 S였는데, 4.6절에서 그 제약이 사실이 아님을 확인했으므로 **같은 FFT를 탐지와 방향이 함께 쓰는 한 경로**로 합친다.

## 7. 대상 소리: 아는 것과 모르는 것

### 7.1 대상을 FPV형으로 잡는다

러우전쟁의 자폭드론은 음향으로 보면 두 종류다. 이 브랜치는 FPV형을 대상으로 잡는다.

| | Shahed형 (피스톤 엔진, 장거리) | FPV형 (멀티로터, 근거리) |
| --- | --- | --- |
| 소리의 원천 | 2행정 엔진과 프로펠러 하나 | 모터 4개 이상, 로터마다 회전수가 조금씩 다름 |
| f0의 추정 | 축 회전수 83~125 Hz, 날개 통과 167~250 Hz | 날개 통과 수백 Hz. 계산 예: DJI FPV 3엽 × 185 Hz ≈ 555 Hz |
| 근거 | `계산` 엔진 최대 출력이 7500 rpm, 2엽 직결·순항 5000~7500 rpm 가정 | `문헌` 검색 요약에서 본 계산 예 하나. 원문과 대조하지 못했고 자폭용 기체의 값도 아님 |
| 속도 | 약 185 km/h. 도플러로 +18% / −13% | 요구사항의 28 m/s 가정과 가까움 |
| 실측 | **없음** | **없음** |

두 값 모두 이 프로젝트에서 잰 것이 아니다. 설계에 쓰기 전에 재야 한다.

### 7.2 2026-10-13 조사 결과

- **Shahed형의 공개 음향 데이터셋은 찾지 못했다.** 엔진 소리로 Shahed를 인식하는 논문은 있으나 데이터(약 15분)는 비공개이고, f0를 수치로 밝힌 문헌도 찾지 못했다.
- **자유 라이선스 영상 4개(위키미디어 공용)는 쓸 수 없었다.** 편집본이라 해설 음성, 인트로 음악, 차량 엔진이 지배한다. 고조파 점수가 가장 높은 구간이 음성과 음악이었다(5.3절의 한계를 실제로 확인).
- **멀티로터의 공개 데이터셋은 있다.** 아직 받아서 돌려 보지는 않았다.

| 데이터셋 | 내용 | 쓸모 |
| --- | --- | --- |
| DroneAudioset (Hugging Face, MIT) | 23.5시간, 기종·스로틀별 | f0 범위, 고조파 수 |
| 32종 드론 데이터셋 (arXiv 2509.04715) | 브랜드·모델별 원음 | 기종 간 차이 |
| Western Sydney 대학 배열 녹음 | DJI Air 3, 24채널, GPS 비행 로그 | 방향 추정 검증까지 가능 |

분석 도구는 `Tools/audio/f0_probe.py`다. wav 파일에 5.3절의 점수를 돌려 f0 분포와 스펙트로그램을 낸다. 합성 신호(117, 210, 95 Hz)에서 116, 209, 93~95 Hz로 읽었고 잡음만 넣으면 검출이 0건이다. 실제 드론 소리로는 아직 검증하지 못했다.

### 7.3 대상이 FPV형이면 달라지는 것

아래는 f0가 수백 Hz라는 추정 위의 예상이고, 7.2절의 데이터셋으로 재서 확인해야 한다.

- **f0/Δf는 제약에서 빠진다.** f0 300 Hz면 12.5 kHz·512점(41 ms)으로도 12다. v0.1이 긴 프레임을 필요로 했던 이유(낮은 f0)가 사라지므로, N은 SNR과 반응 시간으로 정한다. 빠르게 움직이는 표적에는 짧은 프레임이 유리하다.
- **쓸 대역 f_use가 올라간다.** f0 500 Hz에 고조파 10개면 5 kHz다. 12.5 kHz 처리(최고 6.25 kHz)에 간신히 들어가고 FIR은 75탭 수준이다. 그 위까지 쓸 만하면 ↓2(25 kHz)로 바꾼다.
- **에너지 대부분이 c/2d 위에 있다.** 14 cm면 1225 Hz, 7 cm면 2450 Hz인데 FPV형의 고조파는 수 kHz까지 간다. c/2d 아래만 쓰면 선이 2~4개뿐이라, 그 위의 선을 쓰는 것이 선택이 아니라 필수가 된다. 5.7절에 따르면 조건은 f0 < c/2d라서 원리상 가능하고, 실제로 되는지 확인하는 일(E7)이 필수 검증이다.
- **후보 f0의 범위를 바꾼다.** v0.1의 80~400 Hz로는 날개 통과 주파수를 놓칠 수 있다.
- **선이 넓다.** 로터 넷의 회전수가 다르고 기동 중에 계속 바뀐다. 마스크 폭과 프레임 길이의 상한이 여기서 정해진다.

## 9. 사전 지식의 사용 범위

| 단계 | 아는 것                                              | 쓰는 곳                       | 처음 보는 드론 위험 |
| ---- | ---------------------------------------------------- | ----------------------------- | ------------------- |
| 1    | 배경 잡음 (상시 학습)                                | SNR, 잡음 바닥                | 없음                |
| 2    | 일반 물리 구조: f0 정수배, f0가 머무는 범위, 천천히 변함 | 고조파 검출, 방향 추정 마스크 | 낮음                |
| 3    | 특정 기종 스펙트럼 (학습 모델)                       | **분류에만** (젯슨)           | 높음                |

**원칙:** 방향 추정은 3단계 지식에 의존하지 않는다. 학습되지 않은 기종이 오면 방향 추정까지 무너지기 때문이다. 재사용되는 것은 f0 값이 아니라 **구조**다. f0는 매 프레임 다시 찾는다.

## 11. 구현 단계

| 단계 | 내용                                                                     | 완료 기준                                                   | 남길 플롯·수치                            |
| ---- | ------------------------------------------------------------------------ | ----------------------------------------------------------- | ----------------------------------------- |
| 4-0  | **FIR + ↓4와 연속 덤프** (STM32). 필터 루프와 버퍼 관리는 직접 구현      | 같은 소리를 50 kHz·1024점 기준선과 비교해 각도가 일치. 무음에서 48.8 Hz 간격의 선이 없음 | 필터 응답, 처리 시간, 각도 차이           |
| 4-1  | 대상 소리의 f0 파악 (PC). 공개 데이터셋에 `f0_probe.py`                  | f0의 범위, 고조파 수, 선의 폭이 숫자로 나옴                 | 기종별 f0 분포, 스펙트로그램              |
| 4-2  | S1 잡음 바닥 + S6 기능저하 감지 (STM32)                                  | 조용/바람/모터/큰 소음 상황에서 바닥 추이와 JAM 플래그 정상 | bin별 잡음 바닥 시간 추이, JAM 판정 지연  |
| 4-3  | 데이터 수집: 배경 잡음 3ch 연속 덤프(상황별), 드론 소리 재생 덤프        | 상황별 데이터셋                                             | 상황별 스펙트럼                           |
| 4-4  | S2 고조파 검출기 PC 프로토타입                                           | 드론 vs 배경 점수 분포 분리                                 | **ROC 곡선** → REQ-PERF-011/012 수치 확정 |
| 4-5  | S4 고조파 마스크 GCC vs BPF+PHAT (PC, 시뮬레이션 + 덤프)                 | SNR −10 dB 이상값 비율 비교. c/2d 위의 고조파 포함 (E7)     | 이상값 비율·RMS vs SNR                    |
| 4-6  | MCU 이식 (FFT, 점수, 마스크 GCC)                                         | 결과가 PC와 일치, U ≤ 70%                                   | DWT 처리시간, PC vs MCU 차이              |
| 4-7  | S3 M-of-N + S5 출력 구조체 + 플래그                                      | SBC 수신 확인                                               | 확정 지연 분포                            |
| 4-8  | (조건부) 교차 스펙트럼 평균, 코히어런스 가중                             | **4-5에서 마스크만으로 부족하다는 숫자가 나온 경우만**      | 마스크 대비 개선량                        |

4-0을 맨 앞에 둔 이유는 연속 덤프가 있어야 4-3 이후의 데이터 수집이 가능하기 때문이다. 4-1은 보드 없이 PC만으로 할 수 있으므로 4-0과 함께 진행한다. 각 단계는 Step3 형식(선택지 → 기준 → 플롯 → 결정 → 결정이 바뀌는 조건)으로 기록한다.

| ------------------------------------------- | ----------------------------------------------------------------------- |
