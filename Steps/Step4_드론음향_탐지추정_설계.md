# Step 4 — 드론 음향 탐지·방향추정 설계 (스냅 검출기 → 드론 대응 전환)

> 문서 상태: 설계 초안 | 작성: 2026-10-13 | 작성자: LSH
> 선행 문서: 요구사항 v0.2, Step3 마이크 기하 결정 (d = 14 cm)
> 이 문서는 현재 동작하는 **스냅(순간음) 방향 검출기**를 **드론(지속 고조파음) 탐지 + 방향 추정**으로 바꾸는 설계 기준이다.

## 1. 왜 바꾸나: 대상 소리의 성질이 정반대

| 성질               | 스냅·박수 (현재 대상)              | 드론 (목표 대상)            |
| ------------------ | ---------------------------------- | --------------------------- |
| 지속 시간          | 수 ms 순간음                       | 수 초 이상 지속             |
| 스펙트럼           | 넓은 대역에 고르게                 | f0의 정수배 선(**고조파**)  |
| 세기               | 가까워서 큼                        | **멀어서 약함**             |
| 유리한 관측 시간 T | **짧게** (긴 프레임은 잡음만 더함) | **길게** (여러 프레임 평균) |
| 유리한 대역        | 넓고 높게                          | 고조파가 있는 bin만         |
| 프레임 정렬        | 시작점에 맞춰야 함                 | 무관                        |
| 트리거             | 큰 소리 (AWD, rms 임계)            | **고조파 구조의 지속**      |

## 2. 파라미터 정리 (이해 교정 포함)

### 2.1 다이얼(제어 파라미터)과 결과값

| 구분                   | 항목                                                                                                                         |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 직접 돌리는 다이얼     | N, Fs, d(14 cm로 결정), 가중 방식(대역 또는 bin 마스크), 평균 시간(지수평균 시정수 또는 프레임 수 M), 창 함수, 신뢰 판정 임계값 |
| 다이얼이 정하는 결과값 | T = N/Fs, Δf = 1/T, S = Fs·d/c, K, β, σ_τ, σθ, 출력 지연, CPU 점유율 U                                                       |
| 다이얼이 아닌 입력값   | 대상 소리의 스펙트럼(f0, 에너지가 있는 고조파, 선의 폭), 배경 잡음. **재서 얻는 값**                                         |
| 지금은 다루지 않음     | 마이크 개수·배치 (성능 문제가 확인되기 전까지)                                                                               |

- K와 β는 직접 고르지 않는다. 가중 방식, T, **대상 소리의 스펙트럼**이 정해지면 따라 나온다.
- 그래서 **가장 먼저 할 일은 대상 소리의 f0와 고조파 구조를 재는 것**이다(10절). 1채널 녹음을 PC에서 스펙트로그램으로 보면 되고, 보드는 필요 없다.
- 신뢰 판정 임계값은 **결과 단위**로 거르는 기준이다(peak, norm, 세 쌍 일치, 직전 각도 대비 점프). bin 단위로 위상 직선에서 벗어난 점을 빼는 방식은 쓰지 않는다. 고조파 마스크가 같은 일을 τ와 무관한 기준으로 먼저 하기 때문이다.

### 2.2 각 변수의 역할

**먼저 구분할 것: "시간" 네 가지**

| 이름      | 뜻                                                                           | 크기               |
| --------- | ---------------------------------------------------------------------------- | ------------------ |
| T         | 한 프레임에 **담긴 소리의 길이** (관측 시간)                                 | 20.48 ms           |
| 처리 시간 | 그 프레임을 CPU가 **계산하는 데 걸리는 시간**                                | 수 ms              |
| τ         | 두 마이크에 소리가 **도달하는 시각의 차이**. 재려는 값                       | 최대 d/c = 0.41 ms |
| 출력 지연 | 소리가 난 뒤 결과가 나오기까지 ≈ T + 처리 시간 (평균을 쓰면 시정수만큼 추가) |                    |

**측정 변수**

| 변수          | 역할                                                                                                                                        | 헷갈리기 쉬운 점                                                                                                                                                                             |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T = N/Fs      | 관측 시간. 길수록 bin이 촘촘해져 K = B·T가 늘고 σ_τ가 줄어든다. 대가는 출력 지연(실시간 반응이 느려짐)                                      | 처리 시간이 아니다. T를 늘려서 커지는 것은 출력 지연이지 τ가 아니다. 각도 오차는 줄어든다. 움직이는 표적만 T 동안 평균되어 번진다(16°/s × 20 ms ≈ 0.3°)                                      |
| Δf = 1/T      | bin 간격 = 주파수를 구분하는 단위. **T가 늘면 줄어든다.** 고조파 간격 f0가 3 bin 이상이어야 선 사이에 잡음만 있는 bin이 생긴다              | FFT 뒤를 0으로 채우면 bin 간격만 줄고 구분 능력은 그대로다. 현재 코드(250샘플 구간, 512점 FFT)의 구분 단위는 97.7 Hz가 아니라 200 Hz                                                         |
| Fs            | (1) 담을 수 있는 최고 주파수 Fs/2 (2) 지연을 재는 시간 눈금. 1샘플 = 1/Fs = 20 µs                                                           | "올리면 bin이 늘어 정밀해진다" → **반대**. N 고정이면 T가 줄어 Δf가 넓어지고 K 감소                                                                                                          |
| S = Fs·d/c    | 최대 지연의 샘플 수 (14 cm, 50 kHz에서 20.4). Fs를 낮추면 S가 줄어 보간에 더 기대게 된다 → 방향 경로는 Fs를 20 kHz 아래로 내리지 않는다     | `TDOA_MAX_LAG`를 S에 맞춰야 한다 (14 cm면 13 → 23)                                                                                                                                           |
| K             | 위상 직선을 맞추는 점(bin)의 개수. 오차 ∝ 1/√K                                                                                              | 잡음을 깎는 것이 아니라, 점이 많아져 오차가 평균으로 줄어드는 것이다. **신호가 있는 bin만** 도움. 잡음뿐인 bin은 PHAT에서 방해                                                               |
| β = √(Σfₖ²/K) | 쓰는 bin들의 원점에서 평균 거리(지렛대). 오차 ∝ 1/β. 고주파 쪽 bin이 지배한다                                                               | 기울기(−2πτ)를 정하지 않는다. 기울기는 음원 방향이 정하고, β는 그 기울기를 **얼마나 정확히 읽는가**를 정한다. 끝점이 아니라 평균 거리다(150~2000 Hz를 고르게 쓰면 약 1200 Hz)                |
| d             | τ를 각도로 바꾸는 지렛대. τ는 최대 d/c까지 변하므로, d가 2배면 같은 σ_τ가 절반의 각도 오차가 된다 (σθ ∝ σ_τ/d)                              | c/2d 제약은 부작용 쪽이다. d를 키우면 c/2d(14 cm에서 1225 Hz)가 내려가고, 대역을 그 아래로 제한하면 β가 같은 비율로 줄어 이득이 상쇄된다. 이 상한은 고조파 음원에서 보수적(Step3 시뮬레이션) |

- **β가 키우는 것은 정밀도다.** 엉뚱한 피크로 튀는 것(신뢰도)은 K와 주파수 다양성 쪽이다.
- **d로 이득을 보는 경우는 두 가지다:** 음원의 에너지가 원래 낮은 주파수에만 있어서 c/2d가 실제 제약이 아닐 때, 또는 c/2d 위의 주파수도 쓸 수 있을 때(마스크로 제한을 푸는 이유, E7로 검증).

**K와 β는 한 덩어리다: β·√K = √(Σfₖ²)**

β 식의 분모 K는 평균을 내려고 나눈 것뿐이다. 정밀도를 정하는 것은 "쓰는 bin들의 주파수 제곱의 합" 하나이고, K(몇 개인가)와 β(평균적으로 얼마나 먼가)는 그것을 둘로 나눠 부른 이름이다.

| K를 늘리는 방법                      | K    | β         | β·√K      |
| ------------------------------------ | ---- | --------- | --------- |
| T를 늘림 (같은 대역에 점이 촘촘해짐) | 증가 | 그대로    | 증가      |
| 대역을 위로 넓힘                     | 증가 | 증가      | 크게 증가 |
| 대역을 아래로 넓힘                   | 증가 | 약간 감소 | 조금 증가 |

예: 1000, 2000 Hz 두 점에 500 Hz를 추가하면 β는 1581 → 1323으로 줄지만 β·√K는 2236 → 2291로 늘어난다. 신호가 있는 bin이라면 낮은 주파수 점도 도움이 작을 뿐 손해는 아니다.

**T를 늘리는 두 방법**

| 방법               | Δf     | S (지연 눈금)     | 처리 시간        | U         | 쓰는 곳                        |
| ------------------ | ------ | ----------------- | ---------------- | --------- | ------------------------------ |
| N을 늘림 (Fs 고정) | 줄어듦 | 그대로            | N·log₂N으로 증가 | 약간 증가 | 방향 경로                      |
| Fs를 낮춤 (N 고정) | 줄어듦 | 줄어듦 (거칠어짐) | 그대로           | 감소      | 탐지 경로 (↓4 데시메이션)      |

- N을 2배로 하면 프레임당 남는 시간은 17.2 → 33.7 ms로 늘지만, 프레임 수가 절반이라 **초당 남는 시간은 839 → 823 ms로 늘지 않는다** (처리 시간 3.3 ms 기준).
- 달라지는 것은 덩어리의 크기다. 마감까지의 여유가 길어지는 대신, 바쁜 구간도 3.3 → 7.3 ms로 길어진다.

**처리 방식 다이얼**

| 다이얼                    | 무엇인가                                                                                             | 드론에서 필요한 이유                                                                                                             | 대가                                                                                    |
| ------------------------- | ---------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 가중 방식 (고조파 마스크) | 어떤 bin을 얼마나 믿을지 정하는 규칙. 고조파가 있는 bin만 무게 1                                     | 드론의 에너지는 f0 정수배에만 있다. 나머지 bin은 잡음뿐이라 PHAT에서 방해가 된다                                                 | f0가 틀리면 신호까지 지운다. f0/Δf가 3 미만이면 이득이 거의 없다(BPF + PHAT 수준)       |
| 평균 시정수 (프레임 수 M) | 교차 스펙트럼 G[k]를 몇 프레임 겹쳐 볼 것인가. 지수평균 Ḡ ← (1−α)·Ḡ + α·G, 시정수 ≈ T/α              | 신호 화살표는 매 프레임 같은 방향이라 M배, 잡음은 방향이 제각각이라 √M배 → 신호가 √M배 두드러진다. α = 0.1이면 0.2 s, 약 19프레임 | 움직이는 표적이 뒤처진다(16°/s × 0.2 s ≈ 3°). 출력 지연                                 |
| 창 함수                   | FFT 전에 프레임 양 끝을 0으로 부드럽게 줄이는 곱셈. **현재 코드는 이미 Tukey(양 끝 20%)를 쓴다**     | 프레임 끝이 이어지지 않으면 에너지가 모든 bin으로 샌다(누설). 강한 대역 밖 음의 누설이 약한 고조파 bin을 덮을 수 있다            | Hann은 누설이 적지만 선이 넓어지고(마스크 폭 최소 2 bin) 가장자리 데이터가 덜 쓰인다    |
| 신뢰 판정 임계값          | 나온 결과를 쓸지 버릴지 정하는 기준. 현재 peak ≥ 0.5, 0.3 ≤ norm ≤ 1.2                               | 연속 처리에서는 세 쌍의 일치, 직전 각도 대비 점프도 기준으로 쓸 수 있다                                                          | 가용률 하락. bin 수가 바뀌면 peak 분포가 달라지므로 다시 정해야 한다                    |

- 평균하는 대상은 각도나 X[k]가 아니라 **교차 스펙트럼 G[k]** 다. X[k]의 위상은 프레임마다 바뀌지만 G[k]의 위상은 유지된다.
- 지수평균은 `capture.c`의 잡음 바닥(`floor_alpha`)에 쓰는 것과 같은 식이다.

### 2.3 핵심 공식

| 식                                      | 의미                                                                                        |
| --------------------------------------- | ------------------------------------------------------------------------------------------- |
| φₖ = −2π·fₖ·τ                           | 지연 τ는 주파수마다 다른 위상 회전 → 위상-주파수 그래프에서 원점을 지나는 직선, 기울기 −2πτ |
| σ_τ = σφ / (2π·β·√K) = σφ / (2π·√Σfₖ²)  | 위상 직선 기울기의 오차 (bin별 위상 잡음 σφ가 같을 때)                                      |
| 1/σ_τ² ∝ Σₖ (2πfₖ)²·SNRₖ                | bin마다 신뢰도가 다를 때의 일반형. bin의 기여 = 지렛대² × 신뢰도                            |
| σθ ≈ (c/d)·√(2/3)·σ_τ                   | 정삼각형 3개 최소제곱 기준 각도 오차                                                        |
| Δf = Fs/N = 1/T                         | bin 간격. 마스크가 의미를 가지려면 f0/Δf ≥ 3 (Hann이면 4)                                   |
| 시정수 ≈ T/α, 유효 프레임 수 ≈ 2/α − 1  | 지수평균의 길이                                                                             |
| U = 처리 시간 / T                       | CPU 점유율                                                                                  |

**지렛대는 두 단이다:** 위상 잡음 σφ → (÷ 2π·β·√K) → 시간 오차 σ_τ → (× c/d) → 각도 오차 σθ. β는 주파수 축의 지렛대(위상 → 시간), d는 공간의 지렛대(시간 → 각도)다.

**고조파 간격이 bin 몇 개인가 (f0/Δf).** f0를 재면 N은 실험 없이 이 표로 판정한다.

| 경로                       | T        | Δf      | f0 30 Hz | 80 Hz | 100 Hz | 200 Hz | 400 Hz |
| -------------------------- | -------- | ------- | -------- | ----- | ------ | ------ | ------ |
| 현재 스냅 코드 (250샘플)   | 5 ms     | 200 Hz  | 0.15     | 0.4   | 0.5    | 1      | 2      |
| 방향 경로 (1024, 50 kHz)   | 20.48 ms | 48.8 Hz | 0.6      | 1.6   | 2.0    | 4.1    | 8.2    |
| 방향 경로 N = 2048         | 41 ms    | 24.4 Hz | 1.2      | 3.3   | 4.1    | 8.2    | 16     |
| 탐지 경로 (2048, 12.5 kHz) | 164 ms   | 6.1 Hz  | 4.9      | 13    | 16     | 33     | 66     |

- 방향 경로 1024점은 f0 150 Hz 이상에서만 여유가 있다. 80~100 Hz는 1.6~2 bin이라 마스크 이득이 거의 없다.
- 간격이 모자라도 방향 추정이 무너지지는 않는다. 마스크가 거의 모든 bin을 덮어 BPF + PHAT 수준으로 돌아가고, 평균의 이득은 그대로 남는다.

## 3. 원리 요약

| 개념                           | 한 줄 설명                                                                                                                      |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| DFT                            | X[k] = Σ x[n]·e^(−j2πkn/N). N개의 화살표(길이 x[n], 각도 −2πkn/N)를 더한 최종 화살표. 길이 = 그 주파수의 양, 각도 = 위상        |
| 교차 스펙트럼                  | G[k] = X₂[k]·conj(X₁[k]). 각도 = 두 마이크의 위상 차이. 위상-주파수 그래프의 점 하나                                            |
| PHAT                           | 모든 G[k]의 길이를 1로 → 모든 점이 한 표씩 = **보통 최소제곱**                                                                  |
| ML 가중 (Knapp & Carter, 1976) | 점마다 무게 = 그 bin 위상의 신뢰도 = **가중 최소제곱**. 스프링 세기가 다른 시소                                                 |
| GCC를 쓰는 이유                | 직선 맞추기는 ±180° 위상 감김을 펴야 하지만, GCC는 화살표를 더하므로 감김 문제가 없음                                           |
| SNR                            | bin이 평소 잡음 바닥보다 얼마나 큰가 → "소리가 큰가"                                                                            |
| 코히어런스                     | 여러 프레임 동안 두 마이크의 위상 차이가 일정한가 → "한 방향에서 일관되게 오는가". 프레임 1개로는 항상 1이므로 반드시 평균 필요 |
| 고조파                         | 주기적으로 반복하는 소리(프로펠러 블레이드 통과)는 f0 정수배에만 에너지. 바람·빗소리 등 비주기 잡음과 구분됨. f0 = RPM 정보     |

**원리 한 줄:** 믿을 만한 주파수 칸의 목소리는 크게, 잡음뿐인 칸은 작게.

## 4. 목표 파이프라인

```
ADC 3ch 50 kHz ─┬─ [S1 잡음 바닥 추적] ─────────────┐
                │                                    ▼
                ├─ [탐지 경로] ↓4 데시메이션 → 12.5 kHz, 2048점 FFT (Δf 6.1 Hz)
                │      → [S2 고조파 검출기: f0 탐색·추적] → [S3 M-of-N 확정]
                │                         │ f0, 고조파 bin
                │                         ▼
                └─ [방향 경로] 50 kHz, 1024점 → 교차 스펙트럼 지수평균
                       → [S4 고조파 마스크 가중 GCC-PHAT] → 보간 → LSE → 방위
                                          ▼
                     [S5 출력 tdoa_meas_t] + [S6 재밍·기능저하 감지]
                                          ▼  UART
                     젯슨: 다중 트랙, 큐 우선순위, 카메라 확인 (S7)
```

| 단계             | 내용                                                                                                                                               | 위치        |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- |
| S1 잡음 바닥     | bin별 지수평균. **미검출 프레임에서만 갱신**. MOTOR_ACTIVE 중에는 갱신 중지(또는 별도 모터 잡음 프로파일)                                          | STM32       |
| S2 고조파 검출기 | f0 = 80~400 Hz 후보마다 S(f0) = Σₖ min(SNR(k·f0), 상한). 최댓값과 f0 출력. f0는 프레임 간 천천히 변한다는 제약으로 추적                            | STM32       |
| S3 확정          | 연속 N구간 중 M구간 이상 검출 시 확정 (초기안 3-of-5)                                                                                              | STM32       |
| S4 방향 추정     | 교차 스펙트럼을 지수평균(시정수 TBD, 초기 0.1~0.2 s)한 뒤, 고조파 bin(±폭)만 무게 1, 나머지 0(또는 작은 값). 이후 IFFT·피크·보간·LSE는 기존과 동일 | STM32       |
| S5 출력          | 요구사항 v0.2 6절 형식 (t_us, az, σ, score, f0, flags)                                                                                             | STM32 → SBC |
| S6 기능저하 감지 | 잡음 바닥 급상승, 클리핑 지속 → JAM 플래그 + 즉시 보고                                                                                             | STM32       |
| S7 융합·큐       | 다중 트랙, 접근 트랙(음량↑, f0↑) 우선, 고정 음원 후순위, 카메라 확인                                                                               | 젯슨        |

**고조파 마스크 폭:** 로터 4개의 RPM 차이(수 %) 때문에 높은 고조파일수록 선이 퍼진다. 폭 = max(1 bin, 0.03·k·f0) 정도에서 시작해 실측으로 조정한다.

**탐지 경로를 따로 두는 이유:** 방향 경로(Δf 48.8 Hz)보다 bin이 8배 촘촘해서 좁은 고조파 선이 잡음 위로 약 9 dB(10·log₁₀ 8) 더 올라온다. 방향 경로는 50 kHz·1024점을 유지한다.

## 6. 탐지 판단 기준: 미탐 vs 오탐

|           | 미탐                  | 오탐                                                                                       |
| --------- | --------------------- | ------------------------------------------------------------------------------------------ |
| 직접 피해 | 대피 실패 → 인명 피해 | 불필요한 경보, 포탑 회전                                                                   |
| 간접 피해 |                       | 회전 중(약 0.65 s) 음향 먹통, 다른 방향 감시 공백, 경보 피로로 시스템을 끔 → **결국 미탐** |

- 설계: 기대 비용 = C*미탐 × P*미탐 + C\_오탐 × 오탐 빈도. 단, 오탐 빈도 상한(운용자 허용치)을 요구사항으로 둔다.
- 구조: **1차 검출은 미탐 최소화(낮은 임계값) → M-of-N으로 오탐 제거 → 카메라 확인**

| 프레임당 오탐 확률 | 시간당 오탐 (175,680 프레임/시간) |
| ------------------ | --------------------------------- |
| 10⁻³               | 176회                             |
| 10⁻⁴               | 17.6회                            |

| 3-of-5 확정 적용 | 구간당 | 확정 후 |
| ---------------- | ------ | ------- |
| 오탐             | 10⁻²   | 약 10⁻⁵ |
| 탐지             | 0.70   | 0.84    |

대가: 확정 지연 = 5구간. 반응 시간 예산 안에서 M, N, 구간 길이를 정한다.

## 7. 사전 지식의 사용 범위

| 단계 | 아는 것                                              | 쓰는 곳                       | 처음 보는 드론 위험 |
| ---- | ---------------------------------------------------- | ----------------------------- | ------------------- |
| 1    | 배경 잡음 (상시 학습)                                | SNR, 잡음 바닥                | 없음                |
| 2    | 일반 물리 구조: f0 정수배, f0 80~400 Hz, 천천히 변함 | 고조파 검출, 방향 추정 마스크 | 낮음                |
| 3    | 특정 기종 스펙트럼 (학습 모델)                       | **분류에만** (젯슨)           | 높음                |

**원칙:** 방향 추정은 3단계 지식에 의존하지 않는다. 학습되지 않은 기종이 오면 방향 추정까지 무너지기 때문이다. 재사용되는 것은 f0 값이 아니라 **구조**다. f0는 매 프레임 다시 찾는다.

## 8. 강건성: 재밍·기만 대응

| 공격                        | 무너지는 것           | 대응 (알고리즘)                                                                  | 대응 (센서)                    |
| --------------------------- | --------------------- | -------------------------------------------------------------------------------- | ------------------------------ |
| 포화 (큰 소음, 클리핑 유발) | 탐지                  | **재밍 감지 → 기능저하 경보, 경계 수준 상향** / 동적 범위 확보                   | 다른 물리 센서(레이더, 열화상) |
| 기만 (가짜 고조파 음원)     | 포탑이 엉뚱한 곳을 봄 | f0 묶음 분리, 운동학 일관성(고정 음원 판별), 다중 트랙 + 접근 트랙 우선          | 노드 분산 → 재머 위치 추정     |
| 타이밍 결합                 | 반응 시간             | 큐 우선순위, 카메라 독점 방지                                                    |                                |
| (확장) 방향 기반 제거       |                       | 적응형 빔포밍으로 재머 방향 null. 마이크 M개 → 최대 M−1 방향. 채널 보정(E2) 필수 | 마이크 4개 이상                |

**원칙:** 센서가 무력화되면 조용히 실패하지 않고 **경보로 바꾼다.** 재밍 감지는 공격 임박 신호다.

## 9. 구현 단계

| 단계 | 내용                                                                     | 완료 기준                                                   | 남길 플롯·수치                            |
| ---- | ------------------------------------------------------------------------ | ----------------------------------------------------------- | ----------------------------------------- |
| 4-1  | S1 잡음 바닥 + S6 기능저하 감지 (STM32)                                  | 조용/바람/모터/큰 소음 상황에서 바닥 추이와 JAM 플래그 정상 | bin별 잡음 바닥 시간 추이, JAM 판정 지연  |
| 4-2  | 데이터 수집: 배경 잡음 3ch 덤프(상황별 수십 프레임), 드론 녹음 재생 덤프 | 상황별 데이터셋                                             | 상황별 스펙트럼                           |
| 4-3  | S2 고조파 검출기 PC 프로토타입                                           | 드론 vs 배경 점수 분포 분리                                 | **ROC 곡선** → REQ-PERF-011/012 수치 확정 |
| 4-4  | S4 고조파 마스크 GCC vs BPF+PHAT (PC, 시뮬레이션 + 덤프)                 | SNR −10 dB 이상값 비율 비교                                 | 이상값 비율·RMS vs SNR                    |
| 4-5  | MCU 이식 (데시메이션, 2048점 FFT, 마스크 GCC)                            | 결과가 PC와 일치, U ≤ 70%                                   | DWT 처리시간, PC vs MCU 차이              |
| 4-6  | S3 M-of-N + S5 출력 구조체 + 플래그                                      | SBC 수신 확인                                               | 확정 지연 분포                            |
| 4-7  | (조건부) 코히어런스 가중                                                 | **4-4에서 마스크만으로 부족하다는 숫자가 나온 경우만**      | 마스크 대비 개선량                        |

각 단계는 Step3 형식(선택지 → 기준 → 플롯 → 결정 → 결정이 바뀌는 조건)으로 기록한다.
