# 학습자 프로필

> 갱신: 2026-10-25 · 이 파일은 프로젝트가 바뀌어도 유지한다.
> 프로젝트에서 틀린 개념은 여기 두지 않는다 ([concepts.html](concepts.html)).
> 초안 — 1절은 사용자가 채운다 ([GUIDE.md](GUIDE.md) 3절, 5문항 이내).

## 1. 배경 (베이스라인 1)

- 전공/경력: 전자공학과 (졸업), EKF/LQR/동역학 모델링 기반 Wheeled Bipedal Robot (졸업논문)
- 익숙한 언어/도구: C (STM32 HAL, CMSIS-DSP), Python (numpy, scipy, matplotlib), STM32CubeIDE
- 설명 선호: 시각화/표 위주 -> (필요한 경우) 수식 -> (요청한 경우) 코드
- **중간 계산 (2026-10-25):** 핵심 개념과 관련된 중간 계산은 당연한 것처럼 생략하지 않는다. 표에 넣는 숫자는 어디서 왔는지 단계별로 보이고, 근거 없는 가정은 가정이라고 밝힌다
- **현재 수준 (2026-10-25 하향 조정, 사용자 요청):** 신호처리 기초 용어를 아직 자유롭게 쓰지 못한다. AI 답변 중 이해하지 못한 것이 많았다.
  - 스펙트럼, dB, 주파수 응답, 나이퀴스트, 필터, 고조파, 파장 같은 말은 **처음 나올 때마다** 쉬운 말과 숫자 예시로 풀어 쓴다. 앞에서 설명했다고 안다고 가정하지 않는다
  - 한 문단에 새 용어는 하나만. "A라서 B이고 그래서 C" 같은 긴 인과 사슬은 한 단계씩 끊어 쓴다
  - 순서: 이 프로젝트의 실제 숫자로 된 예시 → 표나 간단한 그림 → 그다음 일반 원리. 수식은 꼭 필요할 때 한 줄
  - 점검 문항도 이 수준에서 시작한다. 상위 개념을 묻기 전에 그 개념이 기대는 기초를 먼저 확인한다 (GUIDE 7절 "기록 전 배경 확인")
- 개념 정리 선호 형식 (2026-10-22): 긴 교재 대신 개념 하나를 네 칸으로 짧게
  1. **핵심 키워드** — 검색할 수 있는 개념 이름
  2. **간략한 설명** — 그 개념이 무엇인지 1 ~ 2줄 (문항의 정답 풀이가 아님)
  3. **프로젝트 맥락** — 이 프로젝트의 어느 단계·코드·결정에서 왜 필요했는지 1 ~ 2줄 (실제 숫자·파일·함수 이름)
  4. **쓰인 위치** — 단계 문서 링크
  - 공부 자료는 내가 고른다. 설명이 짧기만 하면 맥락이 없어 와닿지 않고, 길면 교재가 된다.
- 문서 형식 선호 (2026-10-22): 구조가 있는 것은 그림 중심 HTML, 절차·기록은 md
  - 바이트 배치·버퍼·클럭·타이밍·상태 흐름처럼 표와 글만으로는 읽기 어려운 것은 그림을 넣은 HTML로 한곳에 모은다
  - 두 문서로 나눈다: **경계 명세**(시스템 사이에 오가는 것의 형식·의미·규칙, 송신 코드 ↔ 수신 코드 대응 — 예: `docs/interfaces.html`)와 **내부 구조**(한 시스템 안의 모듈·데이터 흐름·자원 — 예: `docs/firmware.html`)
  - "프로토콜"은 형식·의미·규칙의 약속이고, 파서·송신 코드는 그 구현이다. 경계 명세에는 약속을 적고, 구현 위치는 대응표로만 잇는다
  - 실행 절차·실험 기록·결정 기록은 md로 둔다

## 3. 목표 직무와 면접 대비 (2026-10-25)

- **목표 직무:** 제어·추정(Controls & Estimation) + 신호처리 임베디드 펌웨어 (학사 신입)
- **면접 대비는 이 학습의 목표 중 하나다.** 트리거 점검(GUIDE 4절)의 문항을 이 직무의 기술면접 질문 형태로 내서, 개발하는 동안 면접 준비가 자동으로 쌓이게 한다 (GUIDE 5절 "목표 직무 반영").

**집중할 역량 3가지**

| 역량 | 면접에서 보여 줄 것 | 대표 질문 형태 |
|---|---|---|
| 1. 실시간 구현 | Timer·DMA·ISR 구조를 설계하고 루프 주기·지터·CPU 부하를 숫자로 말한다 ("주기 20.48 ms, 최대 처리 3.2 ms, 부하 48%") | "이 ISR이 마감을 못 지키면 어디부터 보나?", "공유 변수를 ISR과 메인이 같이 쓰면?" |
| 2. 이산시간 신호·시스템 | 샘플링·앨리어싱·FIR/IIR 설계·위상 지연·연속계 제어기의 이산화. 제어와 신호처리의 공통 언어 | "필터를 넣었더니 제어 루프가 불안정해졌다, 왜?", "데시메이션 전에 왜 저역 필터가 필요한가?" |
| 3. 모델링·상태추정 | 물리 모델을 세우고 실측으로 파라미터를 맞추고, KF의 Q·R이 물리적으로 무엇인지 알고 의도를 갖고 바꾼다 | "R을 10배로 키우면 추정이 어떻게 바뀌나?", "측정이 끊기면 KF는 무엇을 하나?" |

**압도적으로 잘해야 할 1가지: 이론(예측)과 실측의 차이를 보고 원인을 좁혀 찾아내는 능력**
- "시뮬레이션에서는 됐는데 보드에서는 왜 안 되나"를 Logger, Python 및 LA/오실로스코프 plot을 근거로 좁혀 간다.
- 위 세 역량은 이 능력으로 하나로 묶인다. 단계마다 **예측 → 측정 → 차이 → 원인** 한 장을 남긴다.
 - AI는 각 단계별로 남겨야할 핵심 Plot 을 캡처한다. 만약 **LA/오실로스코프가 필요하다면 사용자에게 요구**한다.
