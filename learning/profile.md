## 1. 배경 (베이스라인 1)

- 전공/경력: (사용자 작성)
- 익숙한 언어/도구: C (STM32 HAL, CMSIS-DSP), Python (numpy, scipy, matplotlib, pyserial, scikit-learn, PyTorch), STM32CubeIDE
- 설명 선호: 시각화/표 위주 -> (필요한 경우) 수식 -> (요청한 경우) 코드
- 개념 정리 선호 형식 (2026-10-22): 긴 교재 대신 개념 하나를 네 칸으로 짧게
  1. **핵심 키워드** — 검색할 수 있는 개념 이름
  2. **간략한 설명** — 그 개념이 무엇인지 1~2줄 (문항의 정답 풀이가 아님)
  3. **프로젝트 맥락** — 이 프로젝트의 어느 단계·코드·결정에서 왜 필요했는지 1~2줄 (실제 숫자·파일·함수 이름)
  4. **쓰인 위치** — 단계 문서 링크
  - 공부 자료는 내가 고른다. 설명이 짧기만 하면 맥락이 없어 와닿지 않고, 길면 교재가 된다.
- 문서 형식 선호 (2026-10-22): 구조가 있는 것은 그림 중심 HTML, 절차·기록은 md
  - 바이트 배치·버퍼·클럭·타이밍·상태 흐름처럼 표와 글만으로는 읽기 어려운 것은 그림을 넣은 HTML로 한곳에 모은다
  - 두 문서로 나눈다: **경계 명세**(시스템 사이에 오가는 것의 형식·의미·규칙, 송신 코드 ↔ 수신 코드 대응 — 예: `docs/interfaces.html`)와 **내부 구조**(한 시스템 안의 모듈·데이터 흐름·자원 — 예: `docs/firmware.html`)
  - "프로토콜"은 형식·의미·규칙의 약속이고, 파서·송신 코드는 그 구현이다. 경계 명세에는 약속을 적고, 구현 위치는 대응표로만 잇는다
  - 실행 절차·실험 기록·결정 기록은 md로 둔다
